# AGENTS.md — вход для Codex

## ⛔ DANGEROUS!!!!!!! Зависимости сайта

Никогда не удалять, не очищать и не заменять `node_modules` сайта целиком или частично без
предварительного сообщения владельцу с точной пометкой **`DANGEROUS!!!!!!!`** и его явного
согласия. Это относится также к `npm ci`, `npm prune`, ручной очистке, переносу и любому сценарию,
который сначала удаляет установленные пакеты. До согласия разрешены только проверки без записи.
Если зависимости отсутствуют или повреждены, остановиться, сообщить владельцу и не использовать
чужой `node_modules`, временный `NODE_PATH` или другую рабочую папку как обход.

Общие правила сайта и базы — в [CLAUDE.md](CLAUDE.md). Для редактора сначала прочитать
[состояние процесса](editor/process/README.md), затем `editor/CURRENT_TASK.md`.

Верхний Codex общается с владельцем, координирует работу и вовремя останавливает.
Перед новой или расширенной операцией отдельный [менеджер](editor/process/task-manager.md)
разбирает входящие на доске и выбирает достаточный результат; верхний Codex этот разбор не повторяет.
Функциональный код пишет Claude; технический контроль выполняет отдельный контролёр.
После «принято» выполнять раздел «Рабочая ветка и контрольные коммиты» в TASKS: цель editor,
перенос и запуск разделены; текущая ветка основной папки целью не становится.
Единственный порядок ролей, отбора идей, проверки и приёмки —
[начало TASKS.md](editor/TASKS.md#действующий-процесс).
Читать только относящиеся к нынешнему действию разделы, не весь справочник заданий.

После сжатия контекста восстанавливать цель и следующий шаг из CURRENT_TASK, результат — из
совпадающего с операцией handoff и фактического Git. Историю технической проверки в основной
контекст не переносить. По фразе «проверь Claude» применять [codex-gate](.agents/skills/codex-gate/SKILL.md).

Перекрёстная проверка документов Codex выполняется Claude один раз по изменённому порядку,
без проверки функционального кода. Технический автопроверяющий не читает и не пишет Obsidian;
менеджер задач работает с доской через MCP Obsidian.

Ветки и папки — одна схема из [CLAUDE.md](CLAUDE.md), раздел «Ветки и папки»: `main` для статей в основной
папке, `editor` для кода редактора в единственной копии `accepted-editor`. Новых копий репозитория и веток
без слова владельца не создавать; свои временные копии удалять до отчёта.
