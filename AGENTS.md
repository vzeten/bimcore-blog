# AGENTS.md — bimcore-blog (вход для любого ИИ: Codex, Claude Code и других)

Репозиторий сайта **learn.bimcore.one** (Docusaurus). Единственный файл входа; `CLAUDE.md` рядом только
подключает этот файл. Решение владельца 2026-10-02.

## Статьи — всё здесь, база не нужна
Писать, править, переводить статьи и готовить картинки — по навыку
`.agents/skills/bimcore-content-editor/SKILL.md` и его папке `references/`. Это единственный источник правил
статей (стиль, структура, шапка, MDX, картинки, FAQ, карточка товара, проверки). Штатные компоненты — по
`src/theme/MDXComponents.js`, самодельный HTML вместо них не писать. Статьи публикует только редактор
(кнопка «Опубликовать»): человек-автор (владелец, сотрудник) публикует сам; ИИ без явного разрешения владельца сайта ничего не отправляет на сервер.

## Внутренние правила проекта — в базе владельца
Ветки, код сайта и редактора, процессы помощников — в базе знаний владельца (`it/web/learn/repo-rules.md`,
через MCP obsidian, после `CLAUDE.md` базы и `meta/assistants-global.md`). Нет доступа к базе — такую работу не
начинать и сказать об этом одной строкой; статьи по навыку выше делать можно.

## ⛔ DANGEROUS!!!!!!! Папки вне проекта и пакеты

Помощник не создаёт, не переносит и не удаляет папки вне папки проекта по своему решению: сначала
предупреждает владельца с точной пометкой **`DANGEROUS!!!!!!!`** и ждёт его явного согласия.
Без предупреждения можно: свои временные файлы и папки во временной папке Windows (удаляются после
работы); служебные записи инструментов (`.claude`, `.codex`, кэш npm); внутри папки проекта — в местах,
отведённых правилами проекта (копии операций), но не удалять данные владельца.

С той же пометкой и только после согласия: удалять, очищать, переустанавливать пакеты `node_modules`
этой папки или клона редактора (`npm ci`, `npm prune`, ручная очистка) и ставить пакеты в новую копию.
До согласия — только проверки без записи. До создания копии ведущий определяет нужные проверки и, если
им нужны пакеты, включает точный путь и команду установки в согласование; уже данное точное согласие
повторно не спрашивается; разрешённая установка — до передачи исполнителю и только если она нужна. Если пакеты этой папки или клона отсутствуют либо повреждены,
или повреждены пакеты любой копии — остановиться и предупредить; новая копия без пакетов — норма.
Чужие и родительские `node_modules`, временный `NODE_PATH` или другую рабочую папку как обход не использовать.

## Всегда
- Папка с материалами всегда на ветке `main`; в неё не коммитить, `pull`/`merge`/`reset`/`stash` не делать.
- Прямой `git push` статей запрещён. ИИ отправляет что-либо на сервер (публикация статьи кнопкой, выпуск кода сайта) только по прямому слову владельца сайта.
- Это открытый репозиторий: код и внутренние документы редактора сюда не отправлять; ключи, токены и `.env*` не выводить и не коммитить.
- В конце каждого отчёта о коде — строка «Не на GitHub: …». «Отправить на GitHub» = push; «слить в основную ветку» = merge.
