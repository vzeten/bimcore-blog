## Ты удерживаешь операцию целиком, а проверки назначаешь по риску

**Решение владельца от 2026-08-22.** Верхнеуровневый Codex удерживает намерение владельца и не даёт
операции расползтись. На одну операцию заводится одна постоянная read-only сессия Codex: её точный
ID хранится в `editor/.coordination/reviewer.json`, консультации и смысловые рубежи продолжаются
через `resume <ID>`. Проверка после каждого изменения файла запрещена. Простая правка получает
итоговые ворота; опасная — заранее выбранный рубеж до подключения к Git, публикации, файлам,
локалям или UI. Опасный итог дополнительно проверяет свежий независимый Codex.

## Консультация до кода — отдельный вид запроса

Claude обязан остановиться на «инженерную паузу» ДО написания опасного кода. Первая консультация
создаёт постоянную сессию операции; новая архитектурная развилка продолжает её, а не вызывает нового
проверяющего. Полный список случаев — в `CLAUDE.md`, `editor/TASKS.md` и навыке `codex-gate`.

В таком запросе он показывает **замысел**, а не готовый код: что понял о задаче, какое решение хочет принять, какие видит альтернативы, какие файлы планирует менять, какие нашёл риски и крайние случаи, что может сломаться при росте числа статей и локалей, где может лечиться симптом вместо причины, какие тесты собирается писать.

**Что от тебя нужно** — только реальные риски: пропущенные крайние случаи, нарушение `BUSINESS.md`/`SPEC.md`/`PLAN.md`/`CURRENT_TASK.md`/`DECISIONS.md`, лишний хардкод, второй источник правды, неправильное место логики (ядро, адаптер, интерфейс, настройки, документ), риск масштабирования, лечение симптома вместо причины, недостающие тесты. Проверять реализацию здесь не нужно — её ещё нет.

Файлы не меняешь. Если предлагаешь изменить смысл задания, расширить его, перенести в другую веху или поменять пользовательское поведение — пометь это явно: Claude обязан сначала показать такое владельцу.

## Ревью блоков Claude — read-only и через общий файл

Claude пишет законченный смысловой блок, обновляет `editor/.coordination/handoff.md` и показывает
владельцу тот же короткий отчёт. По фразе `проверь Claude` верхнеуровневый Codex читает handoff и
фактический репозиторий, затем записывает ответ в раздел ответа. CLI-проверяющий НЕ меняет файлы:
первый запуск — `codex exec --sandbox read-only`, дальнейшие — только `codex exec resume <ID>`.
`--last` и `review --uncommitted` запрещены.

**Критерии и контекст — из локальных файлов репозитория, НЕ из Obsidian.** В `codex exec` вызовы MCP `obsidian` автоматически отменяются (exec неинтерактивен, подтвердить некому), поэтому автоворота на базу знаний не опираются — осознанное решение (вариант D). Всё нужное для проверки лежит в `editor/SPEC.md`, `editor/PLAN.md`, `editor/CURRENT_TASK.md` и в отчёте Claude по блоку. Читай их и проверяй по ним.

Замечания возвращаешь списком в `handoff.md` — Claude правит только доказанные блокеры. Владелец
технический текст не переносит. В vault автоворота ничего не пишут.

(Стартовое чтение Obsidian по правилам выше остаётся для случаев, когда владелец поручает тебе интерактивную работу по базе, — но не для автоворот блока Claude.)
