# Итоговая проверка

Итоговая проверка не переписывает статью заново. Она доказывает готовность текущих изменений.

1. Для существующих локалей сверь только подтверждённую дельту RU и соответствующие изменения EN/ES по `localize.md`.
2. Для новой локали сверь всю статью по внутреннему списку фактов, структуры, ссылок, медиа, локализуемого frontmatter и видимого текста MDX/JSX-компонентов. Переводи существующие alt, но не требуй, чтобы alt были у всех изображений.
3. Проверяй ИИ-штампы и неестественные конструкции только в тексте, созданном помощником на EN/ES. Текст автора в RU стилистически не переписывай.
4. Проверь термины Revit в изменённых фрагментах и зафиксируй источник новых соответствий.
5. Запусти целевую проверку. Для блога: `node scripts/content-check.js <путь статьи>`. Для docs: `node scripts/content-check.js --all <путь статьи>`.
6. Перед статусом «готово к публикации» выполни обязательные сборки локалей по [publish-and-check.md](publish-and-check.md).
7. Покажи все новые ошибки и предупреждения автору. Не называй материал готовым, если есть ошибка, непроверенный термин или расхождение в перенесённой дельте.

Аудит отсутствующих alt, улучшение старых изображений и общая доработка статьи всегда выполняются отдельным режимом «Доработать», если автор не включил их в текущую задачу явно.


ИИ публикует только по явному слову автора (того, кто вправе публиковать на сайте) на точный состав; прямой push запрещён всегда. Человек-автор публикует сам кнопкой «Опубликовать».
