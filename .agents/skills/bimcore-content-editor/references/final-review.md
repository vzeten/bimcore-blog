# Итоговая проверка

Итоговая проверка не переписывает статью заново. Она доказывает готовность текущих изменений.

1. Для существующих локалей сверь только подтверждённую дельту RU и соответствующие изменения EN/ES по `localize.md`.
2. Для новой локали сверь всю статью по внутреннему списку фактов, структуры, ссылок, медиа, локализуемого frontmatter и видимого текста MDX/JSX-компонентов. Переводи существующие alt, но не требуй, чтобы alt были у всех изображений.
3. Проверяй ИИ-штампы и неестественные конструкции только в тексте, созданном помощником на EN/ES. Текст владельца в RU стилистически не переписывай.
4. Проверь термины Revit в изменённых фрагментах и зафиксируй источник новых соответствий.
5. Запусти целевую проверку. Для блога: `node scripts/content-check.js <путь статьи>`. Для docs: `node scripts/content-check.js --all <путь статьи>`.
6. Перед статусом «готово к публикации» выполни обязательные сборки локалей по `playbook-publish.md`.
7. Покажи все новые ошибки и предупреждения владельцу. Не называй материал готовым, если есть ошибка, непроверенный термин или расхождение в перенесённой дельте.

Аудит отсутствующих alt, улучшение старых изображений и общая доработка статьи всегда выполняются отдельным режимом «Доработать», если владелец не включил их в текущую задачу явно.

Перед публикацией действует перекрёстная проверка проекта: текст Claude проверяет Codex, текст Codex проверяет Claude. Для черновой лёгкой проверки второй помощник не нужен.

Публикация и push выполняются только после явного разрешения владельца.
