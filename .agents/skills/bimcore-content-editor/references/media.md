# Картинки, обложки и стандарт медиа

Одно правило для всех статей, помощников и редактора. Поле `image` в шапке и что роняет сборку — [frontmatter-and-structure.md](frontmatter-and-structure.md).

## Где лежат файлы

- Картинки статьи — в папке статьи своей локали: новые прямо рядом с `index.mdx`, существующие в подпапке `img/` допустимы. Массовый перенос между схемами не нужен.
- Пути в MDX относительные: `./img-01.png` или `./img/img-01.png`.
- Каждая локаль хранит свою копию, даже если картинки одинаковые. Новые ссылки на файл другой локали, EN или общий `/img/...` из `static/` не заводить. Уже существующие межлокальные и общие ссылки сами по себе не поломка; их исправление — отдельная задача.
- Картинки создавать и править сразу в фактической папке локали внутри папки материалов живого редактора. Отдельные staging-, preview- и publication-папки или копии репозитория для медиа запрещены.
- Неподключённые файлы вслепую не вычищать: удалять только после точной сверки ссылок локали (порядок — `SKILL.md`, «Перед работой», п. 7).
- Картинку другого языка не подставлять: на скриншотах Revit бывает локализованный интерфейс. Исключение — правила испанских инструкций в [localize.md](localize.md).

## Стандарт

| Параметр | Правило |
|---|---|
| Форматы тела | PNG, JPG (JPEG), GIF; ролик WebM — только вставкой ролика в редакторе, до 10 МБ; WebP не вводить |
| Обложка `image:` | PNG или JPG; уже ~600 px не ставить — лучше убрать ключ, подставится общая картинка сайта |
| GIF и WebM | байт в байт, не обрабатываются; GIF не больше 5 МБ |
| Размер | шире 1100 px → 1100 по ширине, высота не ограничена; до 1100 px размеры не меняются |
| Вес | порога нет; редактор после 500 КБ только подсказывает |
| Имена | ASCII без пробелов; `img-NN` по умолчанию, безопасное говорящее имя тоже законно; обложка `cover.png` или `cover.jpg` |

## Обработка

1. **Картинки опубликованной статьи не трогаются**: ни сжатие, ни размер, ни формат, ни имя. Адрес картинки на сайте содержит отпечаток содержимого (`assets/images/img-02-<отпечаток>.png`), любое изменение байтов меняет адрес для Google Картинок. Исключение — только отдельным решением владельца сайта по конкретной картинке. Перенос файла без изменения байтов (например из `img/` рядом с `index.mdx`) адрес не меняет.
2. **Неподвижная картинка новой, ещё не опубликованной статьи обрабатывается один раз** перед первой публикацией, явным действием редактора «Доработать» → «Медиаподготовка»; не при вставке и не массово. Без отдельной команды картинки не сжимать.
3. Алгоритм — конвертер редактора: ширина до 1100 px; готовятся PNG с палитрой 256 и JPEG (прозрачная — только PNG); палитра допускается лишь при близости к исходнику не ниже 40 дБ, иначе PNG без потерь; берётся самый лёгкий вариант. Узкая PNG/JPEG меняется только при выигрыше от 10 % и от 10 КБ; WebP и шире 1100 px — всегда. GIF, анимированные PNG/WebP и WebM не трогаются. Повторный запуск ничего не меняет. Опубликованные файлы конвертер пропускает; если сайт спросить не удалось, не трогает ничего.
4. Практический смысл: скриншот, схема, плоская иллюстрация обычно уходят в PNG; фотография, рендер, плавный градиент — в JPEG. После первой публикации формат остаётся навсегда.
5. Оригиналы перед записью редактор сохраняет в своё служебное хранилище вне статьи, Git и сайта, с манифестом. Кнопки возврата нет: вернуть может помощник по манифесту.
6. `scripts/image-prep.py` редактором не вызывается; вручную его не запускать (при смене расширения он удаляет исходный файл).

## Обложка (картинка для соцсетей)

- Своя на каждый язык, `cover.png` или `cover.jpg` рядом с `index.mdx`, в шапке `image: ./cover.<ext>`. Оригиналы с пробелами или кириллицей в имени переименовать (предупредить автора).
- При публикации обложка, если это возможно, всегда своя. По каждой локали проверить: есть ли в теле неподвижные картинки (PNG/JPG) и заполнено ли `image`.
  - Годная картинка есть, `image` пуст — сделать обложку автоматически: `cover.<ext>` рядом с `index.mdx` из первой подходящей неподвижной картинки тела (оригинал не трогается; у новой статьи — по правилам конвертера с расширением по фактическому содержимому, у опубликованной — побайтная копия), в шапку `image: ./cover.<ext>`. Без остановки и без вопроса автору. Редактор при публикации делает это сам.
  - `image` уже задан — не трогать: это ручной выбор автора.
  - Картинок нет или только анимация — `image` не нужен, остаётся общая картинка сайта. Это не ошибка.
  - Обложку не удалось сделать по технической причине — публикацию не держать, статья уходит с общей картинкой, причину назвать автору предупреждением.
- После выкладки у статьи с годной картинкой `og:image` указывает на её обложку, а не на `social-card.jpg`.
- Обложки уроков — [publish-and-check.md](publish-and-check.md), «Урок Revit».

## Подписи и alt

- Подпись картинки — в `![подпись](./img-01.png)` на языке статьи.
- Существующий alt при переводе адаптируется; отдельный аудит отсутствующих alt — только в режиме «Доработать» ([localize.md](localize.md)).
