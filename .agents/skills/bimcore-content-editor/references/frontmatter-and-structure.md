# Шапка, папки локалей и структура статьи

Канон правил статей (решение владельца 2026-10-02). Источник до переноса — база, `it/web/learn/architecture.md` (инварианты, устройство контента, i18n) и `it/web/learn/playbook-publish.md` (§1–4, «Оформление», «sidebar_label»); теперь единственный источник — этот файл.

Смысл, FAQ и CTA — [quality-standard.md](quality-standard.md); картинки и обложка — [media.md](media.md); проверки — [publish-and-check.md](publish-and-check.md).

## Главный принцип

- Папка = файл = slug = URL. Каждая статья — отдельная папка `<slug>/` с файлом `index.mdx`; одна статья на папку.
- Имя файла `index.mdx` одинаково во всех локалях; URL берётся из имени папки; при смене slug переименовывается только папка.
- Префиксы `01-`, `02-` в имени папки допустимы как порядковый номер: Docusaurus снимает их из URL (`numberPrefixParser`).
- Новые файлы контента — только `.mdx`.

## Раздел сайта

| Тип материала | Папка EN | URL |
|---|---|---|
| Урок-техника («как сделать X») | `docs/lessons/<slug>/` | `/lessons/<slug>` |
| Семейство Revit (инструкция набора) | `docs/guides/families/<slug>/` | `/guides/families/<slug>` |
| Статья блога | `blog/<slug>/` | `/blog/<slug>` |

## Файлы локалей (зеркально, три языка)

- EN — язык по умолчанию, без префикса в URL. RU — `/ru/`, ES — `/es/`.
- Docs (уроки, инструкции):
  - EN: `docs/<раздел>/<slug>/index.mdx`
  - RU: `i18n/ru/docusaurus-plugin-content-docs/current/<раздел>/<slug>/index.mdx`
  - ES: `i18n/es/docusaurus-plugin-content-docs/current/<раздел>/<slug>/index.mdx`
- Блог: EN — `blog/<slug>/index.mdx`; RU/ES — `i18n/<locale>/docusaurus-plugin-content-blog/<slug>/index.mdx`.
- Фактические пути проверять по файлам, не угадывать по slug.
- Одну языковую версию статьи в один момент правит только один помощник, чтобы правки не записались поверх друг друга. Перед записью сверить актуальное автосохранение редактора. При расхождении сначала сохранить обе версии и разобрать различия, ничего не затирать. Текст записывать через существующее сохранение редактора с полной согласованной шапкой и актуальным текстом; автосохранение — не запись файла, местная ветка — не опубликованное состояние сайта.
- **RU-only статья не попадает в сборку вообще** (тихо, без ошибки), если в `docs/` нет двойника по тому же slug. Для статьи «пока только на русском» обязательна EN-заглушка: `unlisted: true`, текст «available in Russian only» и ссылка `pathname:///ru/...`. Готовый EN-перевод заменяет заглушку.
- Порядок перевода — [localize.md](localize.md).

## Шапка (frontmatter)

```
---
title: "Полный заголовок"
slug: /<раздел>/<slug>        # docs: АБСОЛЮТНЫЙ, одинаковый во всех локалях
sidebar_label: "Короткое имя в меню"
sidebar_position: <число>
description: "Описание 120–160 знаков на своём языке"
image: ./cover.png            # только ASCII без пробелов; нет картинки — ключ НЕ писать
---
```

**Роняет сборку всего сайта** (Docusaurus проверяет шапку, невалид = белый экран всего сайта, а не одной статьи):
- пустое `image: ''`, пробел или иной недопустимый символ в значении `image`. Допустимо: `cover.png`, `./cover.png`, `./img-01.png`, `/img/...`, `https://...`. Общая картинка сайта для соцсетей уже задана в конфиге: поле в статье нужно только чтобы её заменить;
- невалидный YAML; пустая строка там, где ждут адрес или число.

**Останавливает публикацию в редакторе:** пустой `description` у публикуемой версии; RU-only docs без EN-заглушки.

**Рекомендация, не блокер:** отсутствие `keywords` — предупреждение редактора; `tags` необязательны в блоге и docs; `sidebar_label`/`sidebar_position` для docs желательны.

Правила полей:
- `slug` в docs абсолютный (`/help/foo`), одинаковый во всех локалях; редактор при создании пишет его с префиксом раздела. Префикс не задваивать (`/help/help/...`). В блоге slug относительный.
- Slug опубликованной статьи не менять: адрес уже в поиске. Изменение — только решением владельца.
- Поля меню docs (`sidebar_*`) в блог не переносить. В блоге `date` и `authors` пишет редактор при создании.
- Отсутствующий необязательный ключ не добавлять ради полноты и не писать пустым.
- Видимость (`draft`/`unlisted`) выбирает автор статьи (владелец или сотрудник) в окне публикации редактора; ИИ меняет её только по указанию владельца.
- `description` — содержательный: состав набора или суть урока и что получит читатель, не «Guide by BIMCORE». Он идёт в meta, og, JSON-LD и llms.txt.
- `title` инструкции семейства — по правилу [product-card.md](product-card.md), «Заголовок инструкции».

### sidebar_label

- Короткий и по смыслу (что делаем), не дословный перевод длинного заголовка.
- Для урока источник один: файл описания YouTube урока (`05_youtube_*.md`), раздел «Текст заставки (обложка)» с готовыми RU/EN/ES; строки заставки склеить в одну. Свой перевод не выдумывать, текст с картинки наугад не брать.
- Пунктуацию языка сохранять дословно: вопрос в RU/EN — `?`, в ES — двойной `¿…?`.

## Тело

1. Первый `# Заголовок` исходника убрать: H1 Docusaurus делает из `title`.
2. Если есть видео — первым блоком `<YouTube id="ID" title="Заголовок на языке" uploadDate="ГГГГ-ММ-ДД" duration="секунды" description="…" />`. Без `title` и `uploadDate` разметка VideoObject не создаётся. Подробности для уроков — [publish-and-check.md](publish-and-check.md), «Урок Revit».
3. Для инструкции семейства сразу после шапки — `<ProductCard>` ([product-card.md](product-card.md)).
4. Лид, затем разделы `##` (не `#`).
5. Картинки — `![подпись](./img-01.png)`, файл в папке своей локали ([media.md](media.md)).
6. FAQ последним смысловым разделом, затем штатный CTA ([quality-standard.md](quality-standard.md), «FAQ и CTA»).

### Строгий MDX

- Заголовок смыслового блока только в квадратных скобках: `:::tip[Совет]` (синтаксис блоков — [quality-standard.md](quality-standard.md), «Смысловые блоки»).
- Комментарии в теле только `{/* … */}`; HTML-комментарии `<!-- … -->` запрещены.
- Компоненты — только штатные из `src/theme/MDXComponents.js`; самодельный HTML вместо них не писать.

## Меню и категории

- Меню docs целиком строится из дерева папок (`sidebars.js` = `autogenerated`, `dirName: '.'`). Новая папка `<slug>/index.mdx` в категории появляется в меню сама. `sidebars.js` руками не трогать.
- Категория = папка с `_category_.json` (`{"label":"...","position":N}`); порядок — `position` категорий и `sidebar_position` статей.
- `index.mdx` в корне папки категории — главная страница раздела (не статья); она становится ссылкой-заголовком категории. Создаётся разработчиком при заведении категории; явный `link` в `_category_.json` не прописывать.
- Пустая категория без единого документа роняет сборку всего сайта. Чтобы скрыть раздел, но сохранить структуру, в папке лежит заглушка с `unlisted: true` (как у Help и Courses); категория, где все документы `unlisted`, в меню не показывается — это норма.
- Подписи категорий переводятся ключами `sidebar.mainSidebar.category.<Label>` в `i18n/<locale>/docusaurus-plugin-content-docs/current.json`.
- Особые страницы: `docs/intro.mdx` (главная docs, URL `/`), `docs/guides/families/index.mdx`, `docs/guides/bimcore-plugin/index.mdx`.
- Новую категорию заводит только разработчик или владелец.
