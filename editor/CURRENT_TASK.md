# «Доработать»: выбираемые автоматизации рутины

## Результат

Владелец назначил 2026-09-06 полноценное действие «Доработать»: оно убирает программируемую рутину
подготовки статьи, а не только показывает проверки. Рабочая `feature/editor-refine-automation`,
база `cf59e8d`, целевая `editor`, класс 3: запись шапки, текста и файлов медиа. Claude Fable пишет
код; Codex координирует и проверяет. Без merge, push и публикации.

## Пользовательский сценарий

1. Кнопка доступна только для сохранённой открытой версии и открывает окно выбора; само открытие
   ничего не меняет. Окно показывает только применимые действия, каждое отдельным флажком и с
   точным предпросмотром количества, значений и файлов.
2. По умолчанию выбраны заполнение пустых технических полей и медиаподготовка. Переименование
   картинок и создание обложки из первого изображения по умолчанию выключены.
3. Человек нажимает «Применить». Перед записью сервер сверяет снимок статьи и медиа; изменение
   снаружи даёт отказ без единой записи.
4. Все выбранные действия применяются как одна операция: либо целиком, либо прежние байты всех
   файлов восстанавливаются. Перед записью создаётся обычная версия статьи. После успеха окно
   перечитывает статью и показывает точный отчёт «изменено / оставлено / требует человека».
5. Затем выполняются существующие быстрые проверки «Доработать». Они остаются в отчёте. Кнопка
   публикации, её проверки, сборка, состав, подтверждение, commit и push не меняются.

## Независимые обработчики первого набора

### 1. Технические подписи медиа

Заполняются только пустые значения по шаблонам из настроек. Markdown-картинка, включая GIF,
получает alt; YouTube и WebM — доступное название; ProductCard — `imageAlt`. Готовое значение не
трогается. Шаблон может использовать существующие факты (`title`, номер по порядку, имя товара),
но не вызывает ИИ и не сочиняет смысл вне шаблона. В отчёте видны старое и предложенное значения.

### 2. Пустые поля шапки

Заполняются только поля, для которых в настройках есть явный шаблон или значение либо уже существует
однозначное правило программы: например, автор из настроек создания, короткое имя из `title`,
`slug` из пути. Готовые поля не меняются. Описание, `keywords`, `tags`, дата и другие
смысловые или временные значения без надёжного источника не выдумываются и остаются в отчёте как
работа человека.

### 3. Медиаподготовка

Только уже согласованный алгоритм `scripts/image-prep.py`: неподвижные JPG, PNG и WebP уменьшаются
до 1000 px по длинной стороне, переводятся в RGB, затем в PNG с адаптивной палитрой 256 цветов и
сохраняются с оптимизацией. Меньшее изображение не увеличивается. При смене расширения обновляются
все ссылки открытой версии. GIF и WebM не пережимаются. Отчёт показывает имя, размеры и вес
«было -> стало». Второй рецепт, подбор качества или распознавание вида картинки запрещены.

### 4. Переименование картинок

Отдельный изначально выключенный обработчик. Только локальные картинки, действительно используемые
открытой версией, получают свободные безопасные имена по `картинки.шаблонИмени` и порядку в статье;
все ссылки и импорты обновляются. Cover не становится картинкой тела. Чужой файл не затирается,
безопасное пользовательское имя без выбранного действия законно.

### 5. Обложка из первого изображения

Отдельный изначально выключенный обработчик. Работает лишь при пустом поле `image` и отсутствии
своей обложки: первая используемая неподвижная картинка тела копируется, прогоняется тем же
медиастандартом, сохраняется под свободным `картинки.имяОбложки`, а путь записывается в шапку.
Исходная картинка остаётся. Существующая обложка не заменяется; GIF и WebM не используются.

## Архитектурные границы

- Один реестр описывает порядок, подпись, значение по умолчанию и реализацию обработчиков. Окно и
  маршрут не содержат фильтр по именам: новый обработчик появляется одной регистрацией и своими
  настройками и тестом, без изменения старых обработчиков.
- Единый договор обработчика: чистый анализ снимка -> предложение без записи -> применение к
  рабочей копии -> проверка результата. Обработчики не вызывают друг друга и не знают интерфейс.
- Общая оркестрация отвечает за снимок, порядок, конфликт, атомарную запись, откат, историю и отчёт.
  Правила конкретной автоматизации в ней не дублируются.
- Использовать существующие разбор MDX и frontmatter, правило имени и истории. Не строить второй
  редактор, новый формат статьи, фоновую очередь, плагины времени выполнения или новый конвейер
  публикации. Новых зависимостей без доказанной невозможности не добавлять.
- Ориентир до 900 новых или изменённых строк функционального кода суммарно. Если честная реализация
  требует больше 1200 либо изменения маршрута публикации, остановиться с `REFRAME_REQUIRED`, а не
  прятать объём в мелких файлах. Каждый файл остаётся не длиннее 300 строк.
- Чужие статьи, локали, незадействованные медиа, sandbox владельца и untracked не трогать. Для
  проверок использовать временный стенд и удалить его до сдачи.

## Обязательная проверка до кода

Класс 3: до функциональных правок Claude вызывает одного контролёра только для чтения. Он проверяет
границы записи, атомарность, порядок зависимых обработчиков (переименование, сжатие, cover),
возможность расширения без условий в окне и отсутствие касания публикации. `SHRINK` или
`REFRAME_REQUIRED` останавливает код и возвращается Codex.

## Приёмка

- План ничего не пишет; применение одного флажка не запускает остальные.
- Готовые alt, подписи и поля шапки не меняются; пустые получают ровно показанные значения.
- Медиаподготовка по свойствам соответствует `scripts/image-prep.py`; GIF и WebM неизменны.
- Переименование и cover не выполняются без своих флажков; коллизия имён не затирает файл.
- Любая ошибка или устаревший снимок оставляет статью и все медиа побайтово прежними.
- Меняется только открытая локаль и её используемые файлы; соседние статьи и локали не меняются.
- После успеха окно показывает действительный текст и шапку и точный состав; версия до операции
  доступна в истории. Обычное сохранение, Undo/Redo, замена и вставка изображения и WebM работают.
- Старый сценарий поздних ответов «Доработать» остаётся зелёным.
- Публикационные файлы функционально не меняются; её адресные проверки проходят без обновления
  снимков. Полный `editor:test`, typecheck, corpus и одна живая проба обязательны.

## Завершение

Контрольный коммит только файлов этой операции. `run-status`: operation=`refine-automation`,
branch=`feature/editor-refine-automation`, base=`cf59e8d`, target=`editor`, точный head,
`running -> ready_for_review/owner_required/failed`. Handoff до 50 строк с составом, проверками,
отклонениями и точным сценарием владельца. Видимую сессию Claude после конечного статуса не закрывать.
