# «Доработать»: автоматизация рутины перед публикацией

## Результат

В ветке `feature/editor-refine-automation` от `cf59e8d` кнопка «Доработать» открывает независимое
окно выбора действий, показывает точный план без записи и применяет подтверждённое одной файловой
операцией. Публикация не вызывается и не меняется.

## Обработчики

1. Заполнить только пустые технические подписи изображений, видео и карточек по шаблонам настроек.
2. Заполнить только пустые допустимые поля шапки из уже известных данных.
3. JPG, PNG и WebP пропустить строго через `scripts/image-prep.py`; GIF и WebM оставить побайтово.
4. Опционально переименовать используемые медиа по согласованному шаблону и обновить ссылки.
5. Опционально создать `cover` из первого подходящего изображения, только если обложки нет.

Первые три действия включены по умолчанию, последние два выключены. Готовые значения не
перезаписываются, смысловые данные не выдумываются, кодовые ограды не считаются медиа, коллизии имён
не схлопывают файлы и уходят человеку. Реестр является единственной точкой добавления обработчика.

## Границы этой операции

- План ничего не пишет. Перед записью повторно сверяются статья, имена и байты исходных медиа; после
  последней сверки до первой записи нет асинхронного промежутка.
- Статья и медиа откатываются вместе при штатно перехваченной ошибке. Ошибка отката перечисляет
  невосстановленные пути и не обещает отсутствующую копию медиа в истории.
- Черновик и служебное состояние обслуживаются только после успешной файловой операции; их сбой
  показывается предупреждением и не выдаётся за отмену уже записанного.
- Повторный запрос плана немедленно забывает старый план и отпечаток. Ошибка нового запроса не может
  показать или применить прежний предпросмотр.
- Если выбранным обработчикам нечего менять, «Применить» недоступна, но прежние проверки статьи
  запускаются отдельной кнопкой без записи статьи и истории.
- Работает только открытая локаль и её используемые файлы. Чужие статьи, локали и sandbox не трогать.

## Приёмка

- Адресные тесты покрывают пять обработчиков, умолчания, повторный план, отсутствие изменений,
  устаревший снимок, запись и откат, ограды кода, коллизии, настоящий `image-prep.py`, GIF и WebM.
- Пройдены typecheck, корпус без переписывания, публикационные регрессии без обновления снимков и
  полный `editor:test`; старый красный тест процесса отделён сравнением с базой.
- Суммарное физическое добавление функциональных файлов и настроек не больше 1200 строк; каждый файл
  не длиннее 300 строк. Новые зависимости, обработчики и изменения публикации запрещены.
- Живая проба на временной статье проверяет план без записи, ошибку повторного плана, отсутствие
  изменений с отдельной проверкой, гонку, умолчания, переименование и cover.

## Завершение

Контрольный коммит, handoff до 50 строк и `run-status.json` в `ready_for_review` с точными base/head,
PID и ID сессии. Видимую Claude-сессию не закрывать; владельцу отдавать только после итогового `GO`.
