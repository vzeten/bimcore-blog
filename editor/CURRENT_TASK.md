## Польза

Владелец измеряет влияние публикаций на показы и переходы в Google без ручной таблицы.

## Результат (достаточно)

1. **События «Действия».** Успешная публикация = коммит, дошедший до серверной `main` (`origin/main`) и затронувший
   файл статьи сайта. Запись: статья, локаль, путь, адрес, дата коммита, автор, коммит, точная дельта (строки +/−
   и изменённые поля шапки); описание пустое. Источник один для публикаций владельца и сотрудника: история
   `origin/main`, читаемая при обновлении базы; публикационный код не меняется. Коммиты кода (`editor/`, `src/`,
   настройки сайта) событиями не считаются. Ключ записи — (коммит, путь): повтор дубликатов не создаёт.
2. **Ручное SEO-событие** — отдельный тип записи (дата, текст, необязательный адрес), без смешения с публикациями;
   в операции 1 — только хранение и запись через ручку, кнопок нет.
3. **Search Console:** дневные показы, переходы, CTR и позиция по странице (`page` × `date`), тем же служебным
   доступом и ключом, что GA4 (`C:/My_keys`), только чтение, не чаще `обновлениеЧасов`; последние неполные дни
   помечены. Повторный импорт дня заменяет его, а не удваивает.
4. **Хранилище:** SQLite (`node:sqlite`, встроен в Node 22) в `<материалы>/editor/.analytics/` со своим `.gitignore`;
   доступ только через модуль-границу, которую можно заменить серверной базой без изменения потребителей.
5. **Приватность:** «Поиск Google» есть только там, где есть ключ и база; у сотрудника (нет ключа) ручка отвечает
   «нет функции» без надписей об ошибке. Секрет не попадает в Git, ответ окну, журналы и базу.
