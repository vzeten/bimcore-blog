# Обычный ввод абзацев в существующем редакторе

## Результат

Человек нажимает `Enter` в обычном тексте и продолжает писать новый абзац: курсор и набранное не
возвращаются в предыдущий. `Shift+Enter` переносит строку внутри текущего абзаца.

Базовый коммит: `1e9bd26bfd459b695688e1b78d11f40655d9c538`

Рабочая ветка: `feature/editor-enter-paragraph`

Целевая ветка: `editor`

Класс: 2. Меняется текст, который создают две клавиши.

## Контракт

- В обычном абзаце `Enter` создаёт разделитель абзацев, который понимает Docusaurus.
- В обычном абзаце `Shift+Enter` создаёт жёсткий перенос строки внутри того же абзаца.
- После первой набранной буквы текст остаётся там, где человек видел курсор.
- В списках, заголовках, таблицах, коде и MDX-конструкциях сохраняется нынешнее поведение клавиш.
- Использовать уже подключённый разбор Markdown CodeMirror. Новый разборщик не создавать.
- Нетронутый текст статьи не переписывается и не нормализуется.

## Жёсткие границы реализации

- Не менять CSS, живой показ, изображения, JSX, вставку блоков и правила пустых строк вокруг них.
- Не добавлять зависимость, универсальную модель блоков или новый движок редактора.
- Рабочая правка — один небольшой обработчик клавиш в существующем слое редактора.
- Не более 80 добавленных или существенно переписанных строк рабочего кода; тесты считаются
  отдельно. Если этого недостаточно, остановиться до кода и объяснить причину через handoff.
- Существующую незакоммиченную `editor/sandbox/proba/img-02.png` не трогать и не коммитить.

## Проверка

1. В конце обычного абзаца: `Enter`, слово — появился устойчивый новый абзац.
2. Посреди абзаца: `Enter` — текст разделился на два абзаца без потери символов.
3. `Shift+Enter` — один видимый перенос внутри абзаца, такой же после повторного открытия.
4. `Enter` в списке продолжает список; заголовок, таблица, код, изображение и JSX не изменились.
5. Сохранение и повторное открытие сохраняют полученный MDX; без действий файл не меняется.

Один адресный набор тестов, типы и один полный прогон выполняются после готовой правки. Владелец
проверяет только сценарии 1, 3 и список. Затем верхнеуровневый Codex проверяет точный коммит.

## Точка остановки

Не продолжать исправление визуальных отступов и не выбирать новый редактор. До живой пробы не
переносить ветку в `editor` и не делать push.
