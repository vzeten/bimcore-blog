# Удобные вложенные списки в теле статьи

## Результат

В процессе «Ручное создание статьи и её языковых версий без ИИ» человек набирает обычный
маркированный или нумерованный список, меняет уровень пункта клавишами `Tab` и `Shift+Tab`,
продолжает список клавишей `Enter` и выходит из него без ручного подсчёта пробелов Markdown.
После сохранения и повторного открытия структура остаётся той же и на сайте выглядит как список.

Это первая короткая операция внутри более широкой области «удобное создание тела статьи».

## Класс риска

Класс 2: меняются редактирование и выдаваемый MDX статьи.

## Границы этой операции

- Сначала воспроизвести и кратко зафиксировать нынешнее поведение простого и вложенного списка.
- Поддержать одинаковое изменение уровня у маркированного и нумерованного списка.
- Не заставлять человека вручную вводить нужное число пробелов.
- Сохранить совместимость с разметкой уже существующих статей и Docusaurus.
- Не менять публикацию, локали, историю, комментарии, ИИ и свойства статьи.
- Не добавлять сейчас вставку из Word, изображения внутри пункта, CTA, карточки, YouTube и
  `<truncate />`: это соседние части той же области, а не забытые требования.
- Не менять стили списков сайта без отдельно доказанной необходимости.
- Не заменять редактор и не вводить новую крупную зависимость ради этой операции. Если нынешний
  механизм принципиально не позволяет получить результат малой правкой, остановиться с
  `REFRAME_REQUIRED`, а не строить новый редактор.

## Приёмка

На копии статьи человек может:

1. создать маркированный список из трёх пунктов;
2. сделать второй пункт вложенным через `Tab` и вернуть его через `Shift+Tab`;
3. повторить тот же путь с нумерованным списком;
4. добавить соседний пункт через `Enter` и выйти из списка привычным действием;
5. сохранить, закрыть и повторно открыть статью без изменения структуры;
6. увидеть в локальной сборке Docusaurus ту же вложенность без повреждения соседнего текста.

Адресные проверки покрывают изменение уровня, начало и конец списка, пустой пункт и сохранение.
После последней правки выполняются проверки класса 2 из `TASKS.md`.

## Точка остановки

Claude оставляет редактор открытым на тестовой статье и показывает владельцу только короткий путь
живой пробы. Коммит и push выполняются по действующему процессу после наблюдений владельца и
сверки верхнеуровневого Codex.
