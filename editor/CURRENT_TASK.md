# Опубликованная неизменённая версия не называется черновиком

## Результат

В реестре и открытой статье владелец должен видеть правдивую готовность версии. Если файл версии
есть в опубликованной ветке и его содержимое совпадает с диском, показывается `Опубликована`, даже
когда старый файл состояния содержит `Черновик`. После локальной правки снова показывается сохранённая
незавершённая стадия; программа не скрывает неопубликованные изменения.

Сейчас ошибка воспроизводится на реальной версии
`i18n/ru/docusaurus-plugin-content-blog/free-revit-families-risks/index.mdx`: она опубликована в
`origin/main`, совпадает с ней, а соседний `_state.json` содержит `Черновик`. Текущее правило отдаёт
этому старому значению безусловный приоритет, вопреки `SPEC 4.5.2`.

## Снимок

- operation: `published-readiness-truth`; class: `2`; state: `prepared`.
- branch: `fix/editor-published-readiness`.
- base: `521b60ebcfe2d37065071dc8d61704f6e4a3d7b4`.
- target: `editor`.
- В base уже влита нынешняя `origin/main`, поэтому живая проба относится к опубликованной статье,
  а не к специально подготовленному примеру.

Реальный риск изменения: ложное `Опубликована` может спрятать локальную правку. Поэтому совпадение
с опубликованной веткой должно доказываться содержимым конкретной версии, а не одним наличием пути.

## Границы этой операции

- Исправить единый расчёт готовности и оба места его показа через существующий общий источник.
- Не менять и не переписывать статью, `_state.json`, публикацию, удаление, локали и их оформление,
  фильтры, красные точки, «Доработать» и размещение медиа.
- `Опубликована` остаётся вычисляемым значением и никогда не записывается в файл состояния.
- Если опубликованную ветку нельзя прочитать, не показывать ложный успех и не менять данные.
- Использовать существующий путь чтения Git и не заводить второе правило публикации.

## Приёмка и остановка

- Адресные проверки на временном Git: путь есть и байты равны — `Опубликована` перебивает
  `Черновик`; байты различаются — остаётся сохранённая стадия; пути нет или Git недоступен —
  `Опубликована` не появляется.
- Реестр и шапка открытой статьи получают одно значение из общего расчёта.
- Typecheck, итоговый полный набор один раз, корпус чтения статей и независимый контролёр класса 2.
- Исполнитель запускает редактор и проверяет реальную статью из раздела выше: до изменения файла она
  `Опубликована`, после безопасной локальной правки — не `Опубликована`; затем правку статьи отменяет.

Остановиться на чистом точном коммите и `ready_for_review`. Не исправлять найденные рядом задачи и не
начинать новый интерфейс статусов.
