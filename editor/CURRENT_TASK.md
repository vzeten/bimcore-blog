# Процесс: сторож и технический контролёр

## Результат

Работа Claude завершается однозначным машинным статусом, а одноразовый технический контролёр
передаёт верхнеуровневому Codex короткий проверяемый итог, не меняя продуктовый контракт.

Базовый коммит: `aee5c70dc6d857e69eee97985d5ad15cb04de0e3`

Рабочая ветка: `codex/process-controller-contract`

Целевая ветка: `editor`

Класс: 2. Меняется обязательный процесс приёмки, но не функциональный код редактора.

## Контракт

- Верхнеуровневый Codex хранит продуктовую цель, имеет право остановить, отложить, заменить или
  уменьшить операцию и не читает весь технический diff без блокера либо высокого риска.
- Claude пишет функциональный код и не меняет утверждённый результат по вердикту контролёра.
- `SHRINK` и `REFRAME_REQUIRED` останавливают код: новое узкое задание формулирует верхнеуровневый
  Codex, а не Claude и не контролёр.
- После чистого контрольного коммита Claude пишет в `run-status.json` один из статусов:
  `running`, `ready_for_review`, `owner_required`, `failed`. Свободный текст `handoff.md` не является
  сигналом завершения.
- Для классов 2 и 3 верхнеуровневый Codex запускает один итоговый одноразовый read-only контролёр
  на точном `base..head` и в том же ходе один раз ждёт его завершения; фоновый запуск без ожидания
  запрещён.
- Контролёр возвращает только снимок, вердикт, размер, до трёх доказанных блокеров, до трёх частей
  вне цели и остаточный риск живой пробы. Технических вопросов владельцу нет.
- После `GO` владелец проверяет точный коммит в окне; верхнеуровневый Codex совмещает контракт,
  технический итог и наблюдения владельца и только затем разрешает перенос.
- `handoff.md` остаётся короткой передачей результата и не хранит поток Claude, историю или
  машинный статус.

## Границы этой операции

- Не менять функциональный код редактора, статьи, ProductCard и ветку `feature/editor-product-card`.
- Не создавать новый документ процесса, постоянную сессию контролёра или второго аудитора.
- Не обещать автоматическое уведомление о завершении Claude, пока оно не доказано отдельной пробой.
- Не переписывать историю продукта и не расширять проверку на будущие функции.

## Приёмка

1. Правила ролей и порядок коммит → контролёр → владелец не противоречат друг другу.
2. `SHRINK` не разрешает Claude молча уменьшить контракт.
3. Формат итогового ответа контролёра машинно закреплён и ограничен.
4. Старые `APPROVED_TO_COMMIT` и проба до контрольного коммита отсутствуют.
5. Машинная проверка процесса и `git diff --check` зелёные.
6. Итоговый одноразовый контролёр запущен с ожиданием и его ответ получен без сообщения владельца.

## Точка остановки

Контрольный коммит процесса готов, дерево чистое, итоговый контролёр ответил. Push и перенос в
`editor` не делать до сверки верхнеуровневого Codex.
