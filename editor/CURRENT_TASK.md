## В1-12. Версия при изменении файла снаружи, определение автора

**Зачем это нужно**
Файл статьи меняет не только эта программа. Его правит Claude Code в соседнем окне, правит сотрудник, приносит `git pull`. Сегодня история знает только собственные сохранения, поэтому чужая работа для программы не существует: её не видно в ленте, к ней нельзя вернуться, а кнопка «Сохранить поверх» при конфликте затирает её насовсем — в git она не попала, в истории её нет. Задание закрывает эту дыру и заодно даёт основу для показа правок ИИ отдельным цветом (В1-15).

**Исходные условия**
В1-11 закрыт: черновики, снимки при сохранении, отпечаток файла, конфликт с выбором человека. Снимок умеет хранить время и автора в своём имени (`history.mjs`), но автор сейчас приходит только один — имя из `git config user.name` при нашем сохранении, а при его отсутствии подставляется слово, зашитое в коде.

**Сценарий действий**
Человек уходит из программы или просто не трогает статью. Файл в это время меняет ИИ или приходит `git pull`. Человек открывает статью — программа молча, без вопросов, записывает состояние файла версией: время — когда файл изменился, автор — из сведений git, а если их нет, «Неизвестный». Дальше человек работает как обычно. Если он правил статью, получил конфликт и выбрал «Сохранить поверх», внешняя правка всё равно остаётся в истории и не пропадает.

**Ожидаемый результат**
Ни одна внешняя правка не исчезает бесследно. У каждой версии есть честное время и честный автор: выдуманных имён программа не подставляет.

**Правило автора (единственное место, где оно записано; решение владельца от 2026-08-04)**
Одно правило на всю программу — и для версии внешней правки, и для колонки реестра «Кто менял».

1. Автор из `git log` допустим только для уже закоммиченной правки.
2. Для незакоммиченного файла `git config user.name` автором текста НЕ является: это имя коммиттера по умолчанию, а не доказательство, кто правил файл.
3. Нет явного сведения, кто сделал незакоммиченную правку, — пишется «Неизвестный».
4. Подставлять имя владельца из `git config` для незакоммиченных изменений запрещено: это приписывает владельцу правки ИИ и внешних инструментов.
5. Правка сделана через сам редактор и он записал автора в свой снимок — можно показывать этого автора. Признак «писали мы»: снимок не старше времени изменения файла.
6. Файл изменился снаружи, автора определить нельзя — «Неизвестный», без догадок.
7. Различение Claude и Codex по имени и цвету — это В1-15 и веха 2, если явного следа в состоянии или истории нет.

**База сравнения**
Что программа считает известным состоянием файла: содержимое последнего снимка, а если снимков нет — содержимое файла в опубликованной версии сайта (его сервер уже читает при открытии статьи, лишнего запуска git не будет). Нет и там — известного состояния нет, и первое же увиденное содержимое записывается версией: другой копии у нас не существует.

Отсюда следует граница, которую стоит назвать вслух: правка, которая уже лежит в опубликованной версии сайта, и по которой у нас нет своей истории, версией не становится — её целиком хранит git, и заводить второе хранилище для того же текста запрещено решением «Что и где хранится» в `DECISIONS.md`. Наша история нужна для того, чего у git нет: незакоммиченных состояний.

Сравнивается **полный текст файла** — с невидимой меткой и шапкой, а не одно тело. Иначе внешняя правка шапки (`title`, `slug`, `image`, `unlisted`) не станет версией и потеряется. Сравнение не зависит от переводов строк (SPEC 3.6): переписанный CRLF без изменения текста — не новая версия.

**Правило времени версии**
Время внешней версии — время изменения файла на диске: это момент, когда содержимое здесь появилось. Если оно не позже времени последней известной версии (файл восстановлен из копии, часы сбиты), берётся момент обнаружения. Имена снимков сортируются временем, поэтому версия «из прошлого» встала бы в ленте не туда и первой попала бы под уборку лишних.

**Где программа фиксирует внешнюю версию**
Перед каждой записью в настоящий `.mdx` и при открытии статьи — то есть в трёх местах: открытие статьи, сохранение (до проверки отпечатка и до записи), переключение видимости (тоже переписывает файл). Автосохранение файл не трогает, поэтому четвёртой точкой не становится. Не записалась версия — запись файла не выполняется вовсе: иначе ровно та потеря, которую чинит задание, вернётся через сбой хранилища.

**Ошибки и особые случаи**
Файл не менялся — новых версий не появляется, сколько бы раз статью ни открывали. Внешнее изменение совпало с тем, что уже в окне, — версии нет, сравнение идёт по содержимому. Повторный конфликт подряд даёт одну версию, а не по одной на каждое нажатие «Сохранить». Git недоступен или репозитория нет — версия всё равно записывается, просто с автором «Неизвестный»: потерять содержимое хуже, чем потерять подпись. Внешние версии расходуют тот же предел `снимковНаВерсию`, что и наши сохранения, — уборка лишних работает как раньше. Две версии в одну и ту же миллисекунду с одним автором не затирают друг друга: имя снимка занято — берётся свободное. Фиксация версии не трогает файл статьи ни на байт.

**Что входит**
Чистое правило «есть ли внешняя версия, какое у неё время и какой автор». Чтение последнего снимка с диска. Определение автора по git для одного пути. Вызов правила в трёх местах записи и чтения статьи. Снятие зашитого в коде умолчания для имени автора — слово берётся из настроек. Приведение колонки реестра «Кто менял» к тому же правилу автора (решение владельца). Разгрузка `server.mjs`: git-помощники переезжают в адаптер, иначе файл выходит за предел 300 строк.

**Что не входит**
Показ ленты версий и содержимого версии (В1-13) · возврат к версии (В1-14) · цвет правок ИИ по автору (В1-15) · живое отслеживание файла в открытом окне и подхват правок ИИ с причиной прямо во время работы (веха 2 по `PLAN.md`) · фиксация версий по статьям, которые человек не открывал (обход всех папок контента при тысяче статей — отдельная цена, а пользы без ленты нет).

**Критерии приёмки**

1. Файл изменился снаружи между двумя открытиями статьи — в истории появляется версия с содержимым файла.
2. Файл не менялся — сколько бы раз статью ни открывали, новых версий не появляется.
2.1. Содержимое уже лежит в опубликованной версии сайта, а своей истории у статьи нет — версия не заводится: этот текст целиком хранит git.
3. Автор внешней версии — автор коммита, если правка пришла коммитом.
4. Файл изменён без коммита — автором записывается слово из настроек, а не имя владельца и не значение, зашитое в коде.
5. Реестр в колонке «Кто менял» подчиняется тому же правилу: незакоммиченный файл без явного следа в истории — «Неизвестный», а не имя из `git config user.name`.
6. Правка сделана самим редактором и записана снимком — автором показывается тот, кто записан в снимке.
7. Время версии — время изменения файла; если оно не позже последней известной версии, берётся момент обнаружения.
8. «Сохранить поверх» при конфликте не теряет внешнюю правку: её содержимое остаётся в истории.
9. Не удалось записать версию — файл не переписывается, человек получает ошибку.
10. Повторные конфликты подряд не плодят одинаковые версии.
11. Переключение видимости тоже сначала фиксирует внешнюю правку, потом пишет файл.
12. Статьи нет в опубликованной версии сайта и снимков нет — первое открытие сохраняет её содержимое версией.
13. Изменилась только шапка — это тоже новая версия.
14. Изменились только переводы строк — это не новая версия.
15. Версия хранит полный текст файла: невидимая метка и шапка на месте.
16. Фиксация версии не меняет файл статьи.
17. Git недоступен — программа не падает, версия пишется с автором «Неизвестный».

**Обязательные машинные тесты**
Имя каждого теста повторяет формулировку правила. Проверяется поведение — что вернула функция и что лежит в хранилище, а не наличие строк в коде (SPEC 5.2.1). Первыми пишутся три: внешнее изменение становится версией; «Сохранить поверх» не теряет внешнюю правку; неизвестный автор берётся из настроек (в тест подаётся другое слово, и оно должно оказаться в имени снимка). Обязательны также: правка одной шапки; сохранность метки и шапки в снимке; CRLF без изменения текста версии не создаёт; откат времени при старом времени файла; отсутствие дублей при повторном конфликте; занятое имя снимка не затирается.

**Риски**
`server.mjs` уже 298 строк при пределе 300 (SPEC 4.9), поэтому обвязка уходит в адаптер, а серверу остаются вызовы. Внешние версии расходуют общий предел `снимковНаВерсию` и при болтливом ИИ могут вытеснить наши сохранения — предел настраивается, отдельного предела для внешних не завожу, пока нет ленты и спроса. Ключ `реестр.неизвестныйАвтор` начинает читаться и историей: одно слово в одном месте лучше двух одинаковых слов в двух разделах настроек.

**Зависимости** — В1-11 (снимки и отпечаток файла), В1-20 (хранилище состояния).

**Связанные пункты `SPEC.md`** — 3.6 сравнение не зависит от переводов строк, 4.3 одно правило — одно место, 4.4.1 умолчаний в коде, повторяющих настройку, не бывает, 4.6 чистые функции, 4.7 внешний мир через адаптеры, раздел 6 «Обработка ошибок».

## Ручной чек-лист UI (повторять перед сдачей любого задания, затрагивающего редактор)

Эти баги уже чинились и легко возвращаются: юнит-тестами интерфейс не покрыт, поэтому проверка — живая, по шагам. Пройти в браузере (`npm run editor:dev`, `http://localhost:4780`).

1. **Клик по строкам под картинкой попадает точно.** Открыть статью с картинкой (например «Кресла для Revit»), прокрутить к картинке, кликнуть по строкам сразу под ней — курсор встаёт в кликнутую строку, а не в соседнюю. Проверить и на повторном открытии той же статьи (картинка из кэша — отдельная ветка `img.complete`).
2. **Правка подписи картинки.** Клик по самой картинке — курсор встаёт на её строку, исходный `![alt](src)` раскрывается как текст, `alt` можно поменять.
3. **Кнопка «назад» браузера.** Из открытой статьи нажать «назад» — возвращает в реестр, а не выходит из программы. Повторное «назад» не роняет программу.
4. **Всплывающее меню выделения.** Выделить слово в первой строке — панель «Форматировать / Комментировать» видна и не уходит за верх окна; у нижнего края экрана — падает под выделение.
5. **Видимость и готовность.** Открыть опубликованную статью — готовность «Опубликована» (не «Черновик»); переключатель видимости в шапке меняет надпись «в меню сайта» / «только по ссылке».
6. **Сбой сохранения не теряется молча.** (Подменить `/api/article/save` на 500 в консоли.) После «Сохранить» — панель ошибки, кнопка осталась «Сохранить» (не «Сохранено»), текст правок на месте.
7. **Сбой видимости не меняет состояние.** (Подменить `/api/visibility` на 500.) Надпись видимости не меняется, показана панель ошибки.
8. **Сервер переживает битый запрос.** `curl -X POST /api/article/save --data-binary 'не json'` → 400 JSON `{error}`; то же с `{"path":null,"body":"x"}` и с телом без `body` → 400, а не 500; следом `/api/articles` → 200.
9. **Автосохранение (В1-11).** Поправить текст, дождаться статуса «Автосохранено», обновить страницу — правка на месте, файл `.mdx` в git не изменён. Нажать «Сохранить» — статус «Сохранено», черновик исчез.
10. **Внешняя правка становится версией (В1-12).** Открыть статью, закрыть; поправить её файл сторонним редактором; открыть снова — в `editor/.history/<статья>/` появился снимок с содержимым файла и автором «Неизвестный». Файл `.mdx` при этом не изменился.
