# Блок «Совет» как на сайте

## Результат

Человек вставляет в тело статьи блок «Совет», пишет его текст и видит в редакторе тот же смысловой
блок, который Docusaurus покажет на сайте. Служебные строки `:::tip` руками вводить не нужно.

Базовый коммит: `8ee12fd4072f1b084a8b919459c6565590043ac7`

Рабочая ветка: `feature/editor-tip-block`

Целевая ветка: `editor`

Класс: 2. Меняются вставка и запись текста статьи.

## Контракт

- Существующий корректный блок `:::tip ... :::` показывается в редакторе цельным блоком «Совет»,
  а не россыпью служебных строк.
- Пользователь выбирает `+ Вставить` → `Совет`; блок появляется отдельным элементом в месте
  курсора, а человек сразу может написать текст совета.
- Нажатие на существующий совет позволяет исправить его текст без ручного изменения `:::`.
- Если у блока есть собственный заголовок в квадратных скобках, он сохраняется и показывается.
  Без собственного заголовка используется обычное название совета для открытого языка.
- Сохранение и повторное открытие дают корректный MDX, который собирается Docusaurus.
- Нетронутый блок сохраняется дословно; соседний текст и другие блоки не переписываются.

## Границы этой операции

- Только `:::tip`. `note`, `warning`, `caution`, `danger`, `info` сейчас не добавлять.
- Не менять `ProductCard`, YouTube, CTA, изображения, списки, Enter/Shift+Enter и публикацию.
- Не добавлять зависимость, новый разборщик Markdown или универсальную систему будущих блоков.
- Использовать существующий разбор Markdown CodeMirror и нынешние приёмы живого показа.
- Не более 180 добавленных или существенно переписанных строк рабочего кода; тесты отдельно.
  Если этого недостаточно, остановиться до расширения архитектуры и объяснить причину.

## Приёмка

1. Открыть живую статью с `:::tip`: совет выглядит цельным блоком, текст и заголовок верны.
2. В тестовой статье вставить «Совет», написать две строки, сохранить и открыть заново.
3. Изменить текст существующего совета; служебные границы и соседний текст не повреждены.
4. Собрать временную статью с обычным и озаглавленным `:::tip` через Docusaurus.
5. Без действий файл статьи не меняется.

Один адресный набор тестов, типы и полная сборка выполняются после готовой правки. Владелец
проверяет сценарии 1–3. Затем верхнеуровневый Codex проверяет точный коммит рабочей ветки.

## Точка остановки

До живой пробы не переносить ветку в `editor`, не делать push и не начинать `ProductCard`.
