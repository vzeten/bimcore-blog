# Красная точка только для реального изменения локали

## Результат
Красная точка у RU, EN или ES появляется только тогда, когда фактический публикуемый состав этой
локали отличается от `origin/main`. Ветка, из которой читаются материалы, и постороннее состояние
рабочей папки не создают ложную точку.

## Подтверждённая причина
- Один источник материалов уже принят в `editor`; его не переделывать.
- `расхождениеССайтом` в `src/adapters/gitFile.mjs` объединяет сравнение с `origin/main` и
  безусловное включение `??` из `git status`.
- Поэтому служебное состояние Git может давать `отличается=true`, даже когда опубликованный состав
  выбранной локали совпадает с `origin/main`.
- Причину повторно не исследовать; исправить сам способ определения фактических различий.

## Границы
- Сравнивать только фактический публикуемый состав выбранной локали с `origin/main`.
- Настоящее изменение текста, медиа, добавление и удаление файла выбранной локали должны давать точку.
- RU, EN и ES независимы; публикация одной локали очищает только её собственное совпавшее состояние.
- `draft`, готовность, заглушки, ссылка, цвета, внешний вид и публикационный механизм не менять.
- Хранение, выбор папки материалов, ветки Git и состав публикации не переделывать.
- Посторонние статьи и незакоммиченный код не должны влиять на признак выбранной локали.

## Проверка и остановка
- Адресный тест сохраняет доказанный случай: содержимое локали равно `origin/main`, но папка
  материалов находится на другой ветке или содержит служебное состояние; результат `false`.
- Адресные тесты подтверждают `true` для реального изменения текста, медиа и удаления файла.
- Проверить независимость хотя бы двух локалей и отсутствие влияния постороннего `??`.

  чистым, пишет handoff и `ready_for_review`.
- Остановиться на одном проверенном коммите; merge, push, публикация и соседние улучшения не входят.
