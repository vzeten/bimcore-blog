# ED-031: единая панель экземпляров редактора

## Результат
Владелец одним ярлыком открывает понятную панель и видит реальное текущее состояние всех
обнаруженных экземпляров BIMCORE Editor. Из неё можно открыть, запустить и безопасно остановить
известный рабочий или испытательный экземпляр без чёрных окон и ручного поиска процессов.

## Снимок
- operation: `instance-control`; class: `2`; state: `implementation`.
- board: `ED-031`.
- branch: `feature/editor-instance-control`.
- worktree: `C:/My_code/bimcore-blog/editor/.coordination/worktrees/feature-editor-instance-control`.
- base: `f5725fedd76156f2d1aa3239290d853c73ba3de2`.
- target: `editor`.
- принятый рабочий экземпляр: `editor@f5725fed`, `http://localhost:4780`, материалы
  `C:/My_code/bimcore-blog`.

## Видимое поведение
- Один основной ярлык открывает аккуратную панель управления, а не отдельный сервер вслепую.
- Для каждого живого экземпляра видны: рабочий/испытательный, работает/остановлен, порт, ветка,
  короткий коммит, папка кода и папка материалов.
- Доступны ясные действия `Открыть`, `Запустить`, `Остановить` только когда они применимы.
- После действия состояние обновляется по факту и результат объясняется обычными словами.
- Рабочий экземпляр использует только `4780`; испытательный запускается на явно назначенном
  свободном порту. Одновременно работающие экземпляры отображаются отдельными строками.
- Неизвестный процесс на ожидаемом порту показывается как препятствие и никогда не завершается.

## Границы этой операции
- Использовать идентичность ED-030 как единственный источник подтверждения живого экземпляра;
  список кандидатов может помогать обнаружению, но не выдаёт устаревшую запись за работающий сервер.
- Не изменять статьи, черновики, историю, публикацию, корзину, Git материалов и формат контента.
- Не строить диспетчер всех процессов Windows, автоматический перебор всех портов и удалённое управление.
- Не включать упаковку, Git-доступ и права сотрудника: это отдельная отложенная карточка `ED-032`.
- Не повторять аудит и полный цикл ED-030; менять его код только в необходимой для панели части.
- Производственные файлы держать небольшими, один файл не более 300 строк.

## Риск и достаточные проверки
Класс 2 из-за реального риска завершить чужой процесс или показать устаревшее состояние, после чего
владелец потеряет незавершённую работу. Остановка разрешена только после живого опознания конкретного
экземпляра и повторной сверки непосредственно перед действием. Нужны адресные проверки успеха,
устаревшей записи, уже остановленного экземпляра и неизвестного процесса; полный набор один раз
после последней функциональной правки, без повторной проверки неизменённой логики ED-030.

## Приёмка и остановка
- Одна живая проба одновременно показывает рабочий `4780`, испытательный экземпляр и порт с
  неизвестным процессом.
- Панель открывает и останавливает только опознанные экземпляры; неизвестный остаётся нетронутым.
- Остановленный экземпляр исчезает из живых либо явно становится остановленным; повторный запуск
  возвращает его на назначенный порт и показывает правильную идентичность.
- Рабочий экземпляр после перезапуска снова читает материалы `C:/My_code/bimcore-blog`.
- Существующий ярлык не заменять до технического `GO` и личной пробы владельца точного коммита.
- Остановиться на чистом контрольном коммите со статусом `ready_for_review`; push/publish запрещены.
