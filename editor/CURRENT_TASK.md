# ED-042: безопасные корневые зависимости редактора

## Результат
Обязательная локальная сборка и штатная публикация заранее и честно проверяют собственные
корневые зависимости проекта. Временные рабочие копии не могут использовать ссылку на корневой
`node_modules`, а их удаление не может пройти через reparse point и очистить внешний каталог.

## Снимок
- operation: `editor-root-dependencies`; class: `3`; state: `in-progress`.
- branch: `fix/editor-root-dependencies`.
- base: `13141eda37f1e27466c7690a3fa9a99c87d9df36`.
- target: `editor`.
- card: `ED-042` в `it/web/learn/data/editor-board.md`.

## Доказательства причины
- Корневой `node_modules` опустел `2026-09-06 23:18:43.942Z`.
- Удаляемая рабочая копия `feature-editor-publish-any-branch` получила mtime
  `2026-09-06 23:18:43.969Z`, через 27 мс.
- В этот интервал Codex выполнял `git worktree remove`; команда шла 27,6 с и закончилась
  `failed to delete / Permission denied`.
- Ранее внутри этой копии был junction `node_modules` на
  `C:\My_code\bimcore-blog\node_modules`.
- Claude сохраняет исходные журналы и формулирует границу доказуемости; не объявляет абсолютную
  причинность там, где нет прямого журнала каждого удалённого файла.

## Границы этой операции
- До кода отдельный контролёр проверяет границу хранения и удаления.
- Не создавать junction/symlink `node_modules` во временных рабочих копиях.
- Добавить раннюю проверку локальных зависимостей и нужной версии сборщика; чужие `node_modules`,
  `NODE_PATH` и зависимости другой рабочей копии не считаются успехом.
- Безопасный общий cache допустим только вне удаляемого дерева и не заменяет локальную установку.
- Уборка рабочей копии сначала находит и разрывает reparse points, сверяет их target и отказывает
  при неоднозначности; рекурсивно следовать по ним запрещено.
- Восстановление только из lock-файла и только после отдельного согласия владельца.
- Не менять статьи, локали, публикационный состав, `main`, текущую публикацию и материалы владельца.
- Не выполнять `npm ci`, `npm prune`, удаление или замену `node_modules` без сообщения
  `DANGEROUS!!!!!!!` и явного согласия владельца.

## Приёмка
- Windows-тест доказывает сохранность внешнего target и отказ при junction внутри удаляемой копии.
- Проверка с пустым/чужим `node_modules` останавливает сборку понятной ошибкой до публикации.
- После разрешённого восстановления зависимости берутся из корня этой рабочей папки,
  локальная сборка проходит, исходники и материалы не меняются.
- Один итоговый контролёр класса 3 проверяет точный `base..head`.
- Остановиться на чистом точном коммите и `ready_for_review`; настоящую публикацию не выполнять.
