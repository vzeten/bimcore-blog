# Управление draft у каждой локали
## Результат
Владелец может увидеть и изменить `draft` открытой языковой версии независимо от того, было ли
поле раньше записано вручную, редактором или ИИ. Красное состояние означает только `draft: true`.
Старая опубликованная версия без поля остаётся обычной и не переписывается при открытии.

## Границы этой операции
- У каждой существующей локали в свойствах есть явное управление `draft`.
- `draft: true` показывает включённое состояние и красный признак только этой локали.
- `draft: false` и отсутствие поля равнозначны: режим выключен, красной окраски нет.
- Выключение удаляет поле либо следует действующему правилу записи пустых/ложных полей; не оставлять
  два независимых источника истины.
- Изменение применяется только к открытой локали обычным сохранением и само ничего не публикует.
- Открытие и сохранение без изменения `draft` не дописывают поле в старую статью.
- Новая обычная статья и создаваемая языковая версия получают `draft: true` по сценарию Б1.
- Не менять публикацию, `unlisted`, готовность, миграцию корпуса, статьи, заглушки и страницы разделов.
- Не исправлять соседние визуальные или редакторские замечания.

## Приёмка и остановка
- Адресные тесты: старая статья без поля; `draft: false`; `draft: true`; переключение туда и обратно;
  независимость RU/EN/ES; новая статья и новая локаль.
- Для отсутствующего поля простое открытие и сохранение не меняют байты файла.
- Переключение меняет только выбранную локаль, не публикует её и сохраняется после перезапуска.
- Красный признак есть только при фактическом `draft: true` и одинаков в реестре и шапке.
- Типы, полный набор один раз, корпус чтения/записи без переписывания статей, сборка при изменении MDX,
  проба на копии статьи и итоговый контролёр класса 2.
- Исполнитель оставляет чистый контрольный коммит и точный адрес живой пробы.
Остановиться на `ready_for_review`. Полная миграция и ED-026 про страницы разделов не входят.
