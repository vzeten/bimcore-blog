# Локальные ветки операций редактора

## Результат

Работа над редактором больше не ведётся незакоммиченным слоем поверх `main`. Каждая новая
возможность или починка получает локальную рабочую ветку и контрольные коммиты; в `main` попадает
только результат, принятый владельцем и верхнеуровневым Codex.

Базовый коммит: `80b0bcc`

Рабочая ветка: `codex/editor-operation-branches`

## Границы этой операции

- Изменить только документы процесса, навыки запуска операции и существующий тест договора процесса.
- Не менять функциональный код редактора, статьи, публикацию и настройки сайта.
- Не вводить удалённые ветки, обязательный push, worktree, pull request или новую службу.
- Сохранить действующие живую пробу и проверку по риску; допуск привязать к точному коммиту рабочей
  ветки вместо незакоммиченного индекса.

## Приёмка

1. Новая возможность начинается от чистого `main` в `feature/editor-<суть>`, дефект — в
   `fix/editor-<суть>`.
2. Законченные части и остановка сессии получают локальные контрольные коммиты без вопроса владельцу.
3. Отклонённая операция удаляется вместе с веткой, не меняя `main`.
4. Принятая операция переносится в `main` только после живой пробы и допуска Codex.
5. Если `main` сдвинулся, рабочая ветка сначала синхронизируется, а затронутая проба повторяется.
6. Срочная публикация статьи выполняется из `main`, не смешивая её с кодом рабочей ветки.
7. GitHub и push для рабочей ветки не требуются.

## Точка остановки

Показать владельцу изменённые файлы и результаты проверки согласованности. После принятия сделать
локальный процессный коммит в этой ветке; перенос в `main` выполнить по новому правилу.
