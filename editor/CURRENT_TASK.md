## В1-11. Автосохранение и версии при сохранении

**Зачем это нужно**
Человек закрыл программу, обновил страницу или ушёл из статьи, не нажав «Сохранить», — правки не должны пропадать. При следующем открытии он продолжает с того же места. Плюс каждое настоящее сохранение оставляет версию в истории, чтобы позже можно было вернуться.

**Исходные условия**
Сохранение уже не портит файл (В1-08). Модуль снимков `history.mjs` написан (имена, разбор, сеансы), но к сохранению не подключён. Настроек хранения снимков нет намеренно — заводятся этим заданием вместе с кодом, который их читает.

**Сценарий действий**
Человек правит текст или свойства. Через заданный интервал программа молча пишет рабочий черновик в служебное хранилище редактора вне git — настоящий `.mdx` при этом не трогается. Статус рядом с кнопкой показывает состояние: «Есть несохранённые изменения» → «Сохраняем…» → «Автосохранено». По кнопке «Сохранить» программа пишет настоящий файл, кладёт снимок в историю и убирает черновик; статус — «Сохранено».

**Ожидаемый результат**
Правки не теряются при закрытии окна. Файл статьи меняется только по кнопке. Конфликт с внешней правкой не решается молча.

**Ошибки и особые случаи**
Автосохранение не меняет готовность версии: на сайте ничего не изменилось, пока не нажато «Сохранить» — возврат в черновик происходит только при настоящем сохранении. Черновик, совпадающий с файлом, бесполезен и не предлагается. Битый файл черновика игнорируется и не роняет программу. Протухший черновик (старше срока из настроек) игнорируется. Файл изменился снаружи, а черновика нет — конфликта нет, просто открывается файл. Сбой автосохранения не теряет правки: они остаются в окне, признак несохранённого не снимается, статус «Не удалось автосохранить». Путь неправильного типа или вне репозитория — ошибка запроса, а не падение.

**Что входит**
Запись черновика вне git и вне папок контента. Чтение черновика при открытии статьи. Определение конфликта с внешней правкой по отпечатку файла. Снимок в историю при настоящем сохранении и уборка лишних снимков сверх максимума. Статусы автосохранения в шапке. Настройки хранения — вместе с читающим их кодом.

**Что не входит**
Показ ленты версий (В1-13), возврат к выбранной версии (В1-14), определение автора внешней правки (В1-12), кнопка «Сравнить» как полноценный показ отличий (в этом задании выбор при конфликте — «взять автосохранение» либо «взять файл»).

**Критерии приёмки**

1. Правка текста создаёт черновик в служебной папке редактора; файл `.mdx` при этом не меняется.
2. Правка свойств статьи создаёт черновик так же, как правка текста.
3. Настоящий `.mdx` меняется только по кнопке «Сохранить».
4. Повторное открытие статьи отдаёт содержимое черновика, если он свежее файла, без вопроса к человеку.
5. Если файл на диске изменился после автосохранения, программа сообщает о конфликте и отдаёт оба варианта; молча файл не подменяется.
6. После «Сохранить» черновик исчезает, а в истории появляется снимок.
7. Черновики и снимки не попадают в git.
8. Черновик, совпадающий с файлом, не предлагается как продолжение работы.
9. Битый или протухший черновик игнорируется, программа не падает.
10. Снимков на версию хранится не больше, чем указано в настройках; лишние старые удаляются.
11. Сбой автосохранения оставляет правки в окне и показывает «Не удалось автосохранить».

**Обязательные машинные тесты**
Имя каждого теста повторяет формулировку правила. Проверяется поведение (результат функции и содержимое хранилища), а не наличие строк в коде. Первыми пишутся четыре: черновик пишется вне git; `.mdx` не меняется без «Сохранить»; повторное открытие берёт черновик; конфликт не решается молча.

**Зависимости** — В1-08 (сохранение не портит файл), В1-20 (модуль снимков готов).

**Связанные пункты `SPEC.md`** — 4.4 значения в настройках, 4.7 внешний мир через адаптеры, 5.1 сохранение не портит файл, раздел 6 «Обработка ошибок» (сбой автосохранения ничего не теряет).

## Ручной чек-лист UI (повторять перед сдачей любого задания, затрагивающего редактор)

Эти баги уже чинились и легко возвращаются: юнит-тестами интерфейс не покрыт, поэтому проверка — живая, по шагам. Пройти в браузере (`npm run editor:dev`, `http://localhost:4780`).

1. **Клик по строкам под картинкой попадает точно.** Открыть статью с картинкой (например «Кресла для Revit»), прокрутить к картинке, кликнуть по строкам сразу под ней — курсор встаёт в кликнутую строку, а не в соседнюю. Проверить и на повторном открытии той же статьи (картинка из кэша — отдельная ветка `img.complete`).
2. **Правка подписи картинки.** Клик по самой картинке — курсор встаёт на её строку, исходный `![alt](src)` раскрывается как текст, `alt` можно поменять.
3. **Кнопка «назад» браузера.** Из открытой статьи нажать «назад» — возвращает в реестр, а не выходит из программы. Повторное «назад» не роняет программу.
4. **Всплывающее меню выделения.** Выделить слово в первой строке — панель «Форматировать / Комментировать» видна и не уходит за верх окна; у нижнего края экрана — падает под выделение.
5. **Видимость и готовность.** Открыть опубликованную статью — готовность «Опубликована» (не «Черновик»); переключатель видимости в шапке меняет надпись «в меню сайта» / «только по ссылке».
6. **Сбой сохранения не теряется молча.** (Подменить `/api/article/save` на 500 в консоли.) После «Сохранить» — панель ошибки, кнопка осталась «Сохранить» (не «Сохранено»), текст правок на месте.
7. **Сбой видимости не меняет состояние.** (Подменить `/api/visibility` на 500.) Надпись видимости не меняется, показана панель ошибки.
8. **Сервер переживает битый запрос.** `curl -X POST /api/article/save --data-binary 'не json'` → 400 JSON `{error}`; следом `/api/articles` → 200.
9. **Автосохранение (В1-11).** Поправить текст, дождаться статуса «Автосохранено», обновить страницу — правка на месте, файл `.mdx` в git не изменён. Нажать «Сохранить» — статус «Сохранено», черновик исчез.

Если появится браузерная автоматизация в CI — эти пункты первыми перевести в smoke-тесты. Пока чек-лист заменяет их.
