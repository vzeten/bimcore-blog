# Редирект knowledge.bimcore.one → learn.bimcore.one (Gcore FastEdge)

Постоянный 301-редирект старого сайта базы знаний (bolddesk) на новый Docusaurus.
Цель — увести трафик и SEO-вес без потери позиций Google. Это риск №1 проекта.

## Файлы

| Файл | Что это |
|---|---|
| `index.js` | Функция FastEdge (точка входа) + чистая `resolveRedirect()` |
| `redirect.test.js` | Локальный тест логики (156 проверок, сеть не нужна) |
| `knowledge-sitemap-urls.txt` | Живой список 34 URL старого sitemap (фикстура теста) |

Проверить логику: `node redirect.test.js` (из этой папки).

## Как работает соответствие

Совпадение по **номеру статьи и языку** в старом URL `/{lang}/kb/article/{id}/...`,
а не по точной строке. Поэтому усечённые, со слешем, в другом регистре и
кириллические (`%D1%81urtains`, #21) варианты из индекса Google тоже попадают в цель.
Ни один запрос не отдаёт 404 — неизвестное уходит на главную нужного языка.

Карта id → slug — в `index.js` (`ID2SLUG`), источник истины — `data/articles.md` в базе знаний.

## Развёртывание (порядок)

### 1. Сертификат заранее — без окна простоя (DNS-01)
Обычный Let's Encrypt на Gcore выпускается только ПОСЛЕ переключения DNS (проверка
по живому трафику) — это дало бы 10–30 минут без HTTPS. Обходим через DNS-проверку:

1. В панели Gcore (CDN-ресурс на домен `knowledge.bimcore.one`) запросить сертификат
   Let's Encrypt с подтверждением через **DNS (DNS-01)**.
2. Gcore выдаст значение TXT-записи `_acme-challenge.knowledge.bimcore.one`.
3. Владелец добавляет эту TXT в DNS домена (там же, где живёт CNAME `knowledge`).
4. Gcore проверяет запись и выпускает сертификат — домен ещё указывает на bolddesk,
   посетители ничего не замечают.
5. TXT-запись после выпуска можно удалить.

Если панель DNS не даёт добавить TXT — запасной путь: переключить DNS в тихий час и
принять короткое окно без HTTPS (в `index.js` на этот час можно временно поставить `STATUS = 302`).

### 2. Приложение FastEdge
1. Портал Gcore → FastEdge → HTTP Applications → Create new application.
2. Загрузить собранный из `index.js` Wasm (JS SDK `@gcoredev/fastedge-sdk-js`) или
   вставить код через шаблон.
3. Сохранить и развернуть — получить служебный адрес `https://<app>-<id>.fastedge.app`.

### 3. Проверка на служебном адресе ДО переключения DNS
Прогнать по `*.fastedge.app` (host знать не обязательно — функция подставляет knowledge):
старые пути → 301 на нужные learn-адреса. Только после зелёного прогона трогать DNS.

### 4. CDN-ресурс и переключение домена
1. Создать CDN-ресурс Gcore на custom domain `knowledge.bimcore.one`, привязать
   приложение FastEdge (CDN Applications / Proxy-wasm), подключить сертификат из шага 1.
2. Владелец меняет CNAME `knowledge` со `sslproxy.bolddesk.com` на адрес Gcore
   (TTL сейчас 5 мин — переключение и откат быстрые).

### 5. ⚠️ Включить автопродление сертификата — ОБЯЗАТЕЛЬНО
Ручной сертификат из шага 1 живёт **90 дней**. Сразу после переключения DNS
в настройках CDN-ресурса включить **авто-renew Let's Encrypt (HTTP-01)** — теперь,
когда домен уже на Gcore, он продлевается сам. Без этого через 90 дней knowledge
останется без HTTPS.

### 6. Google Search Console
Добавить ресурсы-префиксы для `https://knowledge.bimcore.one/` и `https://learn.bimcore.one/`
(домен `bimcore.one` подтверждён — новой проверки не нужно), затем подать заявку
«Переезд сайта» (Change of Address) со старого на новый — ускоряет переклейку позиций.

## Откат
`knowledge` — только KB, тикетов на нём нет. Пока подписка bolddesk жива, откат =
вернуть CNAME на `sslproxy.bolddesk.com` (~5 мин). Bolddesk НЕ отменять до 1–2 недель
чистого мониторинга GSC. Внимание: 301 кешируется браузером — поэтому корректность
подтверждаем на `*.fastedge.app` ещё ДО переключения DNS.
