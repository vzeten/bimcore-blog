# Одна правка редактора

До функционального кода прочитать `editor/CURRENT_TASK.md`, относящиеся к операции части
`editor/BUSINESS.md`, `editor/SPEC.md` и карту модулей. Выбрать класс 1, 2 или 3 строго по
`editor/TASKS.md`.

До первой правки проверить записанные в `CURRENT_TASK.md` базовый коммит и рабочую ветку. Новую
возможность писать только в локальной `feature/editor-<суть>`, дефект — в `fix/editor-<суть>`;
прямо в `main` функциональный код не писать. Если сессия продолжает начатую операцию, сначала
сверить текущую ветку и фактический Git с карточкой.

- Класс 1: правка и один проход изменённого экрана; Codex не вызывать.
- Классы 2 и 3: до кода вызвать непостоянного контролёра по `codex-gate`.
- Не менять соседние функции. Рост объёма означает уменьшение операции, а не новый слой.
- После кода выполнить только проверки своего класса и подготовить короткий handoff.
- После законченной смысловой части и перед остановкой сессии сделать локальный контрольный коммит.
  Отдельного согласия владельца для него не нужно; push рабочей ветки без прямого слова запрещён.
- Перед переключением ветки остановить сервер и не оставлять незакоммиченных изменений. Принятие,
  отказ и синхронизация с изменившимся `main` выполняются по `editor/TASKS.md`.

Функциональный код пишет Claude. Codex без прямой просьбы владельца файлы редактора не меняет.
