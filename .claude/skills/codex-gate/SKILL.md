# Codex-контролёр без постоянной сессии

Claude вызывает контролёра только для классов 2 и 3 из `editor/TASKS.md`: один раз до кода и один
раз после законченной правки. Каждый запуск независим, прошлой сессии не продолжает и файлов не меняет.

## Запуск

```powershell
$exe = (Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\bin" -Recurse -Filter codex.exe |
  Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName

Get-Content -Raw $promptPath | & $exe exec --ephemeral `
  -C "C:\My_code\bimcore-blog" --sandbox read-only `
  -m gpt-5.6-sol -c model_reasoning_effort=high -
```

`resume`, `--last`, `review --uncommitted`, сохранение ID и обращение к Obsidian запрещены.
До и после запуска Claude сравнивает `git status --short`: контролёр не должен менять дерево.

## Что получает контролёр

- один результат и границы из `CURRENT_TASK.md`;
- заявленный класс риска;
- до кода: затронутые подсистемы и минимальный план проверок;
- после кода: фактический diff и результаты обязательных проверок;
- если готовится вопрос: точный вопрос и варианты Claude.

Полный журнал сессии, старые замечания, будущий план продукта и документы вне операции не передаются.

## Что он обязан сделать

1. Самостоятельно восстановить цель из `CURRENT_TASK.md` и `BUSINESS.md`.
2. Определить класс по возможному ущербу.
3. Назвать не больше трёх реально затронутых несократимых свойств из `TASKS.md`.
4. Потребовать убрать модуль, состояние, тест или ветку, не нужные для результата.
5. Блокировать только воспроизводимую потерю текста, чужой файл, неверную локаль, ложный успех,
   неправильный коммит, публикацию другого снимка или необратимое удаление.
6. Не ограничиваться вариантами Claude и не переносить технический выбор владельцу.

Стиль, предпочтительная архитектура, будущее масштабирование и искусственный ввод без реального
ущерба не являются блокерами.

## Ответ

Ответ короткий:

```text
Класс: 1 | 2 | 3
Вердикт: GO | SHRINK | BLOCK_REAL_RISK
Вопрос: RESOLVE_WITHOUT_OWNER | REFRAME_REQUIRED | OWNER_REQUIRED
Убрать: <до трёх пунктов или «ничего»>
Блокеры: <до трёх доказанных пунктов или «нет»>
Проверки: <минимальный обязательный набор>
```

`OWNER_REQUIRED` разрешён только при выборе обычного пользовательского поведения или необратимом
риске. Все вопросы операции собираются в один пакет. При `SHRINK` или `REFRAME_REQUIRED` Claude
уменьшает замысел и не показывает вопрос владельцу. После исправления контролёр проверяет только
замечание и обязательный итог, не начинает новый широкий аудит.
