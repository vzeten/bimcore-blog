Вся проектная память (решения, задачи, архитектура, лог, vision) живёт в **Obsidian vault** и доступна **только через MCP obsidian** (`mcp__obsidian__*`), а НЕ через файлы этого репозитория.

- **Vault root:** `C:\My_brain` (реальный путь на диске — `C:\My_brain\My brain\` с пробелом; MCP резолвит сам).
- **НЕ ищи** `CLAUDE.md`, `_index`, `tasks` в этом репозитории через Read/Glob — их здесь нет.

Коротко: во время работы всё новое фиксируй одной строкой в корневом `_inbox.md` базы (дата, автор, домен, суть), статус текущей задачи — сразу в её карточке; раскладка по постоянным файлам — на «гг» (канон — принцип 18 в `meta/principles.md`). Лог пиши событийно; у задачи без критериев приёма — спроси критерии.

### ⛔ Редактор статей — своя папка `editor/` и свои документы

Собственная программа для правки и публикации статей (заменила удалённую Sveltia CMS). Перед любой работой по редактору читать в этом порядке, всё лежит в `editor/`:

1. **`CURRENT_TASK.md`** — **единственный источник текущей цели и следующего шага** (решение владельца 2026-08-15). Что делать прямо сейчас, берётся только отсюда.
2. **`BUSINESS.md`** — зачем программа и что должен уметь человек. Собран из подробного опроса владельца. **Главнее остальных документов** при любом расхождении.
3. **`TASKS.md`** — справочник требований и запас возможных функций: что входит и что НЕ входит, критерии приёмки, класс проверки. **Здесь же правило проверки по риску.** **Очередь работ он больше не задаёт** (решение владельца 2026-08-15).
4. **`MVP.md`** — ближайшие рабочие проверки и история пройденных; очередь работ не задаёт.
5. **`PLAN.md`** — состояние сделанного и живые хвосты (у каждого назван адрес задания).
6. **`SPEC.md`** — обязательные технические правила: инварианты сайта, запреты, устройство кода.
7. **`DECISIONS.md`** — журнал решений, включая правила, перенесённые из удалённой CMS.

Рядом служебные: **`MAP.md`** — карта модулей кода (точка входа при чтении кода), **`JOURNAL.md`** — летопись кругов проверки (на старте не читать), **`IDEAS.md`** — копилка идей по устройству (разбор на границе вехи).

#### Порядок работы — режим пробного MVP (решение владельца 2026-08-15)

- **Ближайшая цель — один видимый работающий результат**, а не группа заданий. Следующий результат назван в начале `CURRENT_TASK.md`; ни `TASKS.md`, ни `MVP.md`, ни `PLAN.md` очереди не задают.
- **Результат принят только после личной пробы владельца в окне.** Зелёные тесты и отчёт помощника этого не заменяют.
- **Новая мысль владельца сначала классифицируется**, а не меняет текущий шаг сама: нужно для текущего результата · блокирует безопасность · записать на потом. Классификация показывается владельцу.
- **Проверка идёт по риску** (`TASKS.md`, «Правило проверки по риску»): опасное — тщательно, обратимая правка интерфейса — быстро.
- **Не отменяется ничем:** сохранность текста человека, точный состав коммита по явному перечню, обязательные проверки и полная сборка внутри публикации, отдельное подтверждение перед отправкой на сайт от того, кто публикует (сегодня всегда владелец; режим сотрудника подтверждается перед работой над ним).
- Не делать соседние задания «заодно». Ни один документ не переписывать без явного слова владельца.

Запуск: `npm run editor:dev`, адрес `http://localhost:4780`.

#### ⛔ Правила работы по редактору (нарушать нельзя)

**Роли.** Claude — единственный исполнитель функционального кода редактора. Верхнеуровневый Codex
удерживает намерение владельца, порядок операций и процесс проверки; без отдельной просьбы владельца
код редактора не меняет. CLI-сессия Codex — read-only проверяющий: первый запуск всегда
`exec --sandbox read-only`, последующие продолжают её по точному ID; появились изменения файлов после
запуска — остановиться и сказать владельцу. Верхнеуровневый Codex пишет свой ответ только в
игнорируемый `editor/.coordination/handoff.md` и в документы процесса, когда владелец прямо поручил
их изменить. Fable — read-only советчик по архитектуре и поиску корня ошибки: кода не пишет, Codex
не заменяет (вызов — в навыке `editor-change`). Владелец принимает поведение программы. Спорное,
расширение задания, смена пользовательского поведения и перенос в другую веху — сначала владельцу.

**Непроверенного кода не остаётся, но объём проверок задаётся риском правки.** Одна операция имеет
одну постоянную сессию Codex: консультация до кода на опасной операции выбирает смысловые рубежи,
а не запускает проверку после каждого изменения файла. Простая правка получает итоговые ворота;
опасное основное правило проверяется до подключения к публикации, Git, файлам, локалям или UI;
опасный итог дополнительно читает свежий независимый проверяющий. Живая проверка в окне не снимается
ни с чего, что человек видит. Закрывающий круг у результата один: выполнены критерии, зелены
обязательные команды, пройдена живая проба и нет доказанного блокера. Точные правила — в
`editor/TASKS.md` и навыке `codex-gate`.

**Живая проверка в окне обязательна.** Машинные тесты её не заменяют: все дефекты, которые находил владелец, были видны только в окне. В отчёте всегда сказано, что проверено машиной, что глазами и кем именно.

**Отчёт владельцу — строго по `editor/REPORT.md`; отчёт не по шаблону — не отчёт.** Там шаблон, правила и запреты. Коротко: отчёт пишется с чистого листа от лица человека, который пользуется программой, а не выжимается из инженерной записи; устройство кода, имена файлов, ход работы и круги проверки в нём не появляются. Ворота после блока проверяют отчёт наравне с кодом.

**Технический обмен не носит владелец.** Claude сначала записывает точный короткий отчёт владельцу
и доказательства в `editor/.coordination/handoff.md`, затем показывает тот же отчёт в своём чате.
По фразе владельца `проверь Claude` верхнеуровневый Codex читает общий файл и фактический checkout,
записывает ответ туда же и кратко отвечает владельцу. Владелец возвращает Claude только
`прочитай ответ Codex и продолжай`. ID постоянной сессии проверки живёт в соседнем
`reviewer.json`; оба файла игнорируются Git и не служат историей проекта.

**Инженерная пауза перед кодом обязательна.** План задаёт порядок, но не отменяет мышление: не лечится ли симптом вместо причины, не появится ли второй источник правды рядом с `settings.json`, как решение сломается на десятках статей и трёх языках. Найдено противоречие между документами или между документом и кодом — сказать владельцу, а не решать молча.

**Решения владельца тоже проверяются на крайние случаи.** Его слово главнее, но «он так сказал» не отменяет разбор: правило, заданное словами, прогоняется по крайним случаям, и найденное противоречие приносится ему ДО того, как станет кодом. Ни один человек не продумывает все случаи с первого раза; продумывать их — работа помощника. Молча принять формулировку владельца и построить на ней код — ошибка помощника, а не владельца.

**Что нужно для проверки — лежит в файлах репозитория.** Ворота базу знаний не читают: в неинтерактивном запуске вызовы Obsidian отменяются. Всё необходимое обязано быть в `editor/TASKS.md` (задание и его критерий приёмки), `editor/SPEC.md`, `editor/CURRENT_TASK.md` и в отчёте по блоку. Разовое решение, меняющее критерии, класть в `CURRENT_TASK.md` до запуска ворот.

**На одну рабочую папку — один пишущий помощник.** Второй в это время только читает. Две сессии в одном дереве уже делали одну работу дважды и затирали друг друга.

**Секрет Obsidian.** Bearer token не выводить, не сохранять и не пересказывать — допустимо писать только «Obsidian MCP подключён».

**Порядок работ — в навыках, а не здесь.** Чтобы этот файл не грузился простынёй в каждую сессию, повторяемые процедуры вынесены и вызываются по делу:

- `model-council` — Совет моделей: кто участвует, кто ведёт, **когда он собирается сам без просьбы владельца**, что кладётся в запрос, что делать с итогом;
- `editor-change` — порядок одной правки: карта влияния, границы блока, что читать, какой тест доказывает поведение;
- `editor-live-check` — живая проверка на `localhost:4780`, включая режим «смотрит владелец у экрана»;
- `codex-gate` — ворота: команда, что положить в запрос, что делать с замечаниями и чем заменить их, если Codex недоступен.

### ⛔ Браузерный плагин (Claude in Chrome / Comet) — только крайнее средство

Управление браузером (`mcp__Claude_in_Chrome__*`, скриншоты, клики, навигация) **запрещено для рутинных задач**. Включать его ТОЛЬКО когда:
- задачу иначе никак не решить (нужна живая сессия пользователя, File System Access, измерение в реальном UI), ИЛИ
- альтернатива явно дороже по ресурсам/времени.

Сначала всегда пробовать дешёвые способы: чтение файлов, `curl`/`Invoke-WebRequest`, лог dev-сервера, поиск по коду/докам. Проверка «работает ли сайт / есть ли ошибка» = HTTP-запрос + лог сервера, НЕ браузер. Если кажется, что нужен браузер — сперва спросить себя, нет ли способа без него, и при сомнении спросить пользователя.

**Запрет не касается редактора статей.** Живая проверка программы во встроенном окне на `localhost:4780` обязательна — порядок в навыке `editor-live-check`. Запрет выше относится к внешнему браузеру с вашей живой сессией (Claude in Chrome, Comet) для рутинных задач и его не отменяет.
