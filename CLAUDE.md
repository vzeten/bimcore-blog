Вся проектная память (решения, задачи, архитектура, лог, vision) живёт в **Obsidian vault** и доступна **только через MCP obsidian** (`mcp__obsidian__*`), а НЕ через файлы этого репозитория.

- **Vault root:** `C:\My_brain` (реальный путь на диске — `C:\My_brain\My brain\` с пробелом; MCP резолвит сам).
- **НЕ ищи** `CLAUDE.md`, `_index`, `tasks` в этом репозитории через Read/Glob — их здесь нет.

### Стартовое чтение базы (через `mcp__obsidian__vault_read`)

Когда нужно «свериться с базой» / понять проект — читай в таком порядке (≤30 KB):

### Как вести базу

Все правила (триггеры, шаблоны, автоведение, SPEC-слой) — в vault: `CLAUDE.md` + `meta/operations.md` + `meta/principles.md`. Следуй им.

Коротко: во время работы всё новое фиксируй одной строкой в корневом `_inbox.md` базы (дата, автор, домен, суть), статус текущей задачи — сразу в её карточке; раскладка по постоянным файлам — на «гг» (канон — принцип 18 в `meta/principles.md`). Лог пиши событийно; у задачи без критериев приёма — спроси критерии.

## Код этого репозитория

### ⛔ Редактор статей — своя папка `editor/` и свои документы

Собственная программа для правки и публикации статей (заменила удалённую Sveltia CMS). Перед любой работой по редактору читать в этом порядке, всё лежит в `editor/`:

1. **`BUSINESS.md`** — зачем программа и что должен уметь человек. Собран из подробного опроса владельца. **Главнее остальных документов** при любом расхождении.
2. **`PLAN.md`** — вехи, декомпозиция заданий, статусы, порядок работ.
3. **`SPEC.md`** — обязательные технические правила: инварианты сайта, запреты, устройство кода.
4. **`DECISIONS.md`** — журнал решений, включая правила, перенесённые из удалённой CMS.

Работать только по заданию из `PLAN.md`. Не делать соседние задания «заодно». Ни один документ не переписывать без явного слова владельца.

Запуск: `npm run editor:dev`, адрес `http://localhost:4780`.

#### Ревью законченного блока через Codex

Схема работы по редактору: Claude пишет **законченный блок** → сам даёт отчёт по шести пунктам (что изменено и зачем; какие правила в SPEC/PLAN/CURRENT_TASK; какое поведение теперь гарантируется по действиям пользователя — успех/ошибка/что не меняется; какие тесты это проверяют поведением; какие команды прогнаны с результатом; что осталось вне блока честными хвостами) → **Codex проверяет воротами** → Claude исправляет **только** найденные замечания, без расширения задачи → и лишь после этого начинается следующий блок.

- **Ворота запускает сам Claude** после законченного блока — владелец не дёргает их вручную.
- **Команда — `codex exec --sandbox read-only`, НЕ `review`.** Системное ограничение: `codex review --uncommitted` нельзя совместить с отдельным промптом (`--uncommitted cannot be used with [PROMPT]`), а без промпта Codex ревьюит весь незакоммиченный diff — а `editor/` не закоммичен, и это тащит слишком широкий объём и шум. Поэтому ворота идут через `exec` с точным промптом, ограничивающим проверку файлами текущего блока.
- **Сниппет — PowerShell** (работа в Windows; `codex` не на PATH, путь резолвить динамически, хэш не хардкодить):
  ```powershell
  $exe = (Get-ChildItem "$env:LOCALAPPDATA\OpenAI\Codex\bin" -Recurse -Filter codex.exe | Sort-Object LastWriteTime -Descending | Select-Object -First 1).FullName
  & $exe exec --sandbox read-only "Ты read-only reviewer. Проверь только эти незакоммиченные файлы блока: <список>. Файлы НЕ меняй. Критерии приёмки и правила бери из локальных editor/SPEC.md, editor/PLAN.md, editor/CURRENT_TASK.md. Верни только реальные замечания списком."
  ```
  `--sandbox read-only` — техническая гарантия, что Codex не пишет в репозиторий, а не только обещание.
- **Контроль «Codex ничего не изменил»:** `git status` до и после. Если после появились изменения файлов — это нарушение процесса: остановиться и сразу сообщить владельцу, дальше не идти.
- **Claude — единственный исполнитель.** Codex только возвращает замечания списком. Claude правит только подтверждённые или очевидно реальные проблемы; спорные сначала показывает владельцу.
- **Автоворота НЕ читают Obsidian — и это осознанно (вариант D).** В `codex exec` вызовы MCP `obsidian` автоматически отменяются (`user cancelled MCP tool call`): exec неинтерактивен, `approval: never`, подтвердить некому; доверие между запусками не переносится (проверено). Поэтому ворота опираются только на локальные файлы репозитория.
- **Следствие для Claude:** всё, что Codex должен знать для проверки блока, обязано лежать в `editor/SPEC.md`, `editor/PLAN.md`, `editor/CURRENT_TASK.md` и в отчёте по блоку — не в vault. Разовое решение, влияющее на критерии, Claude кладёт в `CURRENT_TASK.md`/`DECISIONS.md` (а не только в `_inbox` базы), иначе Codex его не увидит.
- **Секрет Obsidian.** Bearer token Obsidian не выводить, не сохранять и не пересказывать — допустимо писать только «Obsidian MCP подключён».

### ⛔ Браузерный плагин (Claude in Chrome / Comet) — только крайнее средство

Управление браузером (`mcp__Claude_in_Chrome__*`, скриншоты, клики, навигация) **запрещено для рутинных задач**. Включать его ТОЛЬКО когда:
- задачу иначе никак не решить (нужна живая сессия пользователя, File System Access, измерение в реальном UI), ИЛИ
- альтернатива явно дороже по ресурсам/времени.

Сначала всегда пробовать дешёвые способы: чтение файлов, `curl`/`Invoke-WebRequest`, лог dev-сервера, поиск по коду/докам. Проверка «работает ли сайт / есть ли ошибка» = HTTP-запрос + лог сервера, НЕ браузер. Если кажется, что нужен браузер — сперва спросить себя, нет ли способа без него, и при сомнении спросить пользователя.
