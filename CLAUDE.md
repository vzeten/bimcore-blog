Базу знаний и этот репозиторий ведут **два помощника — Claude Code и Codex** — по одним правилам; вход для Codex — `AGENTS.md` рядом (короткая ссылка сюда).

## ⚠️ База знаний проекта — в Obsidian, НЕ в этом репозитории

Вся проектная память (решения, задачи, архитектура, лог, vision) живёт в **Obsidian vault** и доступна **только через MCP obsidian** (`mcp__obsidian__*`), а НЕ через файлы этого репозитория.

- **Vault root:** `C:\My_brain` (реальный путь на диске — `C:\My_brain\My brain\` с пробелом; MCP резолвит сам).
- **НЕ ищи** `CLAUDE.md`, `_index`, `tasks` в этом репозитории через Read/Glob — их здесь нет.

### Стартовое чтение базы (через `mcp__obsidian__vault_read`)

Когда нужно «свериться с базой» / понять проект — читай в таком порядке (≤30 KB):

2. `it/web/learn/_index.md` — карта проекта, статус

### Как вести базу

Все правила (триггеры, шаблоны, автоведение, SPEC-слой) — в vault: `CLAUDE.md` + `meta/operations.md` + `meta/principles.md`. Следуй им.

Коротко: во время работы всё новое фиксируй одной строкой в корневом `_inbox.md` базы (дата, автор, домен, суть), статус текущей задачи — сразу в её карточке; раскладка по постоянным файлам — на «гг» (канон — принцип 18 в `meta/principles.md`). Лог пиши событийно; у задачи без критериев приёма — спроси критерии.

## Код этого репозитория

Docusaurus-проект. Контент и код живут в этом репозитории. Детали архитектуры сайта — в базе знаний (`it/web/learn/architecture` через MCP obsidian).

### ⛔ Редактор статей — своя папка `editor/` и свои документы

Собственная программа для правки и публикации статей (заменила удалённую Sveltia CMS). Перед работой
всегда читать `editor/CURRENT_TASK.md`, затем только относящиеся к операции разделы `BUSINESS.md`,
`TASKS.md`, `SPEC.md` и `MAP.md`. `MVP.md`, `PLAN.md` и `DECISIONS.md` не являются обязательной
историей сессии и читаются лишь по точной ссылке из контракта.

- **`CURRENT_TASK.md`** — единственный источник текущей цели и следующего шага.
- **`BUSINESS.md`** — продуктовый смысл; главнее технических документов при расхождении.
- **`TASKS.md`** — требования, классы риска и процесс одной операции; очередь не задаёт.
- **`SPEC.md`** — обязательные технические инварианты.
- **`MAP.md`** — короткий вход к затронутому коду.
- **`MVP.md`, `PLAN.md`, `DECISIONS.md`** — справочная история, хвосты и решения, не стартовое чтение.

Рядом служебные: **`MAP.md`** — карта модулей кода (точка входа при чтении кода), **`JOURNAL.md`** — летопись кругов проверки (на старте не читать), **`IDEAS.md`** — копилка идей по устройству (разбор на границе вехи).

#### Порядок работы — режим пробного MVP (решение владельца 2026-08-15)

- **Ближайшая цель — один видимый работающий результат**, а не группа заданий. Следующий результат назван в начале `CURRENT_TASK.md`; ни `TASKS.md`, ни `MVP.md`, ни `PLAN.md` очереди не задают.
- **Результат принят только после личной пробы владельца в окне.** Зелёные тесты и отчёт помощника этого не заменяют.
- **Новая мысль владельца сначала классифицируется**, а не меняет текущий шаг сама: нужно для текущего результата · блокирует безопасность · записать на потом. Классификация показывается владельцу.
- **Проверка идёт по риску** (`TASKS.md`, «Правило проверки по риску»): опасное — тщательно, обратимая правка интерфейса — быстро.
- **Не отменяется ничем:** сохранность текста человека, точный состав коммита по явному перечню, обязательные проверки и полная сборка внутри публикации, отдельное подтверждение перед отправкой на сайт от того, кто публикует (сегодня всегда владелец; режим сотрудника подтверждается перед работой над ним).
- Не делать соседние задания «заодно». Ни один документ не переписывать без явного слова владельца.

Запуск: `npm run editor:dev`, адрес `http://localhost:4780`.

#### ⛔ Правила работы по редактору (нарушать нельзя)

**Роли и путь результата.** Владелец вместе с верхнеуровневым Codex формулирует один видимый
результат; это становится коротким контрактом в `editor/CURRENT_TASK.md`. Codex обязан сказать «нет»,
отложить, заменить или уменьшить работу, если она не закрывает разрыв до рабочей версии, имеет
достаточный ручной обход, смешивает несколько результатов или несоразмерна пользе. Claude —
единственный исполнитель функционального кода и не меняет продуктовый результат по совету
технического контролёра. После чистого контрольного коммита верхнеуровневый Codex запускает
одноразового read-only контролёра на точном diff, ждёт его итог и только после `GO` отдаёт результат
на пробу владельцу. Завершённая и принятая функция либо пакет редактора переносится из `editor` в
`main` отдельным решением. Настоящую отправку статьи на сайт подтверждает владелец.

**Два файла передачи.** `CURRENT_TASK.md` хранит только контракт действующей операции: результат,
границы, критерии и точку остановки. Новая операция заменяет его целиком. Игнорируемый
`editor/.coordination/handoff.md` хранит только нынешнюю передачу от Claude: короткий результат,
доказательства, наблюдения владельца и ответ верхнеуровневого Codex. Историю, ID сессий и ревизии
эти файлы не копят. Технические тексты владелец между помощниками не переносит.

**Операция живёт в своей локальной ветке.** `editor` хранит принятые операции редактора, а `main` —
статьи, сайт и только завершённые принятые функции или пакеты редактора. Новая возможность начинается
от `editor` в `feature/editor-<суть>`, исправление — в `fix/editor-<суть>`; базовый коммит, рабочая и
целевая ветки записываются в `CURRENT_TASK.md`. В рабочей ветке разрешены контрольные коммиты без
отдельного вопроса владельцу, push запрещён. Принятие, отказ, синхронизация веток и срочная публикация
выполняются строго по разделу «Рабочая ветка и контрольные коммиты» в `editor/TASKS.md`.

**Вопросы владельцу ограничены.** Технических вопросов владельцу быть не может. Если возник
продуктовый вопрос, Claude записывает один собранный пакет в handoff и останавливается. Решение
`RESOLVE_WITHOUT_OWNER`, `REFRAME_REQUIRED` или `OWNER_REQUIRED` принимает верхнеуровневый Codex,
самостоятельно восстанавливая цель и не ограничиваясь вариантами Claude. Вопрос показывается только
если без ответа меняется обычное пользовательское поведение или возникает необратимый риск.
`SHRINK` и `REFRAME_REQUIRED` останавливают код: новый узкий контракт формулирует Codex. Claude не
вправе молча выбросить часть утверждённого результата.

**Проверки назначаются по ущербу.** Три класса и точный набор команд описаны в `editor/TASKS.md`.
Правка интерфейса проверяется быстро. Для класса 2 достаточно одного итогового контролёра; до кода он
нужен только для новой общей границы хранения, публикации, Git, удаления, внешнего сервиса или
секретов. Класс 3 получает контролёра до кода и после точного коммита. Полный прогон после каждой
мелкой починки, постоянная сессия проверяющего, двойной аудит и обязательный совет моделей запрещены.

**Точный порядок завершения.** Claude сам проходит сценарий, фиксирует результат контрольным
коммитом, оставляет чистое дерево, обновляет handoff и ставит в `run-status.json`
`ready_for_review`. Свободный текст handoff не является сигналом окончания. Верхнеуровневый Codex
запускает итогового контролёра, одним ожиданием получает его ответ и после `GO` даёт владельцу
короткую живую пробу точного коммита. Новый функциональный коммит аннулирует и технический итог, и
пробу. Если поведение устраивает и блокеров нет, Codex записывает
`APPROVED_TO_MERGE branch=<name> head=<sha> base=<sha> target=editor`. Несовпадение любой части или
движение `editor` отменяет допуск. Отдельное согласие владельца на технический перенос принятой
операции в `editor` не требуется.

**На одну рабочую папку — один пишущий помощник.** Второй в это время только читает. Совет моделей
не является этапом процесса и допускается лишь при настоящем противоречии продуктовых целей либо
после двух неудачных технических подходов. Повторяемые действия лежат в навыках `editor-change`,
`editor-live-check`, `codex-gate` и редком `model-council`.

**Секрет Obsidian.** Bearer token не выводить, не сохранять и не пересказывать — допустимо писать только «Obsidian MCP подключён».

### ⛔ Браузерный плагин (Claude in Chrome / Comet) — только крайнее средство

Управление браузером (`mcp__Claude_in_Chrome__*`, скриншоты, клики, навигация) **запрещено для рутинных задач**. Включать его ТОЛЬКО когда:
- задачу иначе никак не решить (нужна живая сессия пользователя, File System Access, измерение в реальном UI), ИЛИ
- альтернатива явно дороже по ресурсам/времени.

Сначала всегда пробовать дешёвые способы: чтение файлов, `curl`/`Invoke-WebRequest`, лог dev-сервера, поиск по коду/докам. Проверка «работает ли сайт / есть ли ошибка» = HTTP-запрос + лог сервера, НЕ браузер. Если кажется, что нужен браузер — сперва спросить себя, нет ли способа без него, и при сомнении спросить пользователя.

**Запрет не касается редактора статей.** Живая проверка программы во встроенном окне на `localhost:4780` обязательна — порядок в навыке `editor-live-check`. Запрет выше относится к внешнему браузеру с вашей живой сессией (Claude in Chrome, Comet) для рутинных задач и его не отменяет.
