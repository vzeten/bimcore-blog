Базу знаний и этот репозиторий ведут **два помощника — Claude Code и Codex** — по одним правилам; вход для Codex — `AGENTS.md` рядом (короткая ссылка сюда).

## ⚠️ База знаний проекта — в Obsidian, НЕ в этом репозитории

Вся проектная память (решения, задачи, архитектура, лог, vision) живёт в **Obsidian vault** и доступна **только через MCP obsidian** (`mcp__obsidian__*`), а НЕ через файлы этого репозитория.

- **Vault root:** `C:\My_brain` (реальный путь на диске — `C:\My_brain\My brain\` с пробелом; MCP резолвит сам).
- **НЕ ищи** `CLAUDE.md`, `_index`, `tasks` в этом репозитории через Read/Glob — их здесь нет.

### Стартовое чтение базы (через `mcp__obsidian__vault_read`)

Когда нужно «свериться с базой» / понять проект — читай в таком порядке (≤30 KB):
1. `CLAUDE.md` (в vault, корень) — схема ведения базы знаний
2. `it/web/learn/_index.md` — карта проекта, статус
3. `it/web/learn/tasks-active.md` — активные задачи
4. 1-2 целевых фрагмента по теме сессии (`vault_read` с `target=heading`)

### Как вести базу

Все правила (триггеры, шаблоны, автоведение, SPEC-слой) — в vault: `CLAUDE.md` + `meta/operations.md` + `meta/principles.md`. Следуй им.

Коротко: во время работы всё новое фиксируй одной строкой в корневом `_inbox.md` базы (дата, автор, домен, суть), статус текущей задачи — сразу в её карточке; раскладка по постоянным файлам — на «гг» (канон — принцип 18 в `meta/principles.md`). Лог пиши событийно; у задачи без критериев приёма — спроси критерии.

## Код этого репозитория

Docusaurus-проект. Контент и код живут в этом репозитории. Детали архитектуры сайта — в базе знаний (`it/web/learn/architecture` через MCP obsidian).

### ⛔ Редактор статей — своя папка `editor/` и свои документы

Собственная программа для правки и публикации статей (заменила удалённую Sveltia CMS). Перед любой работой по редактору читать в этом порядке, всё лежит в `editor/`:

1. **`BUSINESS.md`** — зачем программа и что должен уметь человек. Собран из подробного опроса владельца. **Главнее остальных документов** при любом расхождении.
2. **`PLAN.md`** — вехи, декомпозиция заданий, статусы, порядок работ.
3. **`SPEC.md`** — обязательные технические правила: инварианты сайта, запреты, устройство кода.
4. **`DECISIONS.md`** — журнал решений, включая правила, перенесённые из удалённой CMS.

Рядом служебные: **`MAP.md`** — карта модулей кода (точка входа при чтении кода), **`JOURNAL.md`** — летопись кругов проверки (на старте не читать), **`IDEAS.md`** — копилка идей по устройству (разбор на границе вехи).

Работать только по заданию из `PLAN.md`. Не делать соседние задания «заодно». Ни один документ не переписывать без явного слова владельца.

Запуск: `npm run editor:dev`, адрес `http://localhost:4780`.

#### ⛔ Правила работы по редактору (нарушать нельзя)

**Роли.** Claude — единственный исполнитель кода: пишет только он. Codex — только проверяющий: команда всегда `exec --sandbox read-only`, файлы он не меняет; появились изменения файлов после запуска — остановиться и сказать владельцу. Fable — read-only советчик по архитектуре и поиску корня ошибки: кода не пишет, Codex не заменяет (вызов — в навыке `editor-change`). Владелец принимает работу. Спорное, расширение задания, смена пользовательского поведения и перенос в другую веху — сначала владельцу.

**Непроверенного кода не остаётся.** Проверяется каждая операция, включая разметку, стили, настройки, тесты и вынос кода в другой файл: дыры ловились именно на них. Правка после ворот — новый круг ворот, а не хвост прошлого. Блок закончен только тогда, когда последняя проверка видела файлы в текущем виде, а оставшиеся замечания показаны владельцу как осознанные хвосты.

**Живая проверка в окне обязательна.** Машинные тесты её не заменяют: все дефекты, которые находил владелец, были видны только в окне. В отчёте всегда сказано, что проверено машиной, что глазами и кем именно.

**Инженерная пауза перед кодом обязательна.** План задаёт порядок, но не отменяет мышление: не лечится ли симптом вместо причины, не появится ли второй источник правды рядом с `settings.json`, как решение сломается на десятках статей и трёх языках. Найдено противоречие между документами или между документом и кодом — сказать владельцу, а не решать молча.

**Что нужно для проверки — лежит в файлах репозитория.** Ворота базу знаний не читают: в неинтерактивном запуске вызовы Obsidian отменяются. Всё необходимое обязано быть в `editor/SPEC.md`, `editor/PLAN.md`, `editor/CURRENT_TASK.md` и в отчёте по блоку. Разовое решение, меняющее критерии, класть в `CURRENT_TASK.md` до запуска ворот.

**На одну рабочую папку — один пишущий помощник.** Второй в это время только читает. Две сессии в одном дереве уже делали одну работу дважды и затирали друг друга.

**Секрет Obsidian.** Bearer token не выводить, не сохранять и не пересказывать — допустимо писать только «Obsidian MCP подключён».

**Порядок работ — в навыках, а не здесь.** Чтобы этот файл не грузился простынёй в каждую сессию, повторяемые процедуры вынесены и вызываются по делу:

- `editor-change` — порядок одной правки: карта влияния, границы блока, что читать, какой тест доказывает поведение;
- `editor-live-check` — живая проверка на `localhost:4780`, включая режим «смотрит владелец у экрана»;
- `codex-gate` — ворота: команда, что положить в запрос, что делать с замечаниями и чем заменить их, если Codex недоступен.

### ⛔ Браузерный плагин (Claude in Chrome / Comet) — только крайнее средство

Управление браузером (`mcp__Claude_in_Chrome__*`, скриншоты, клики, навигация) **запрещено для рутинных задач**. Включать его ТОЛЬКО когда:
- задачу иначе никак не решить (нужна живая сессия пользователя, File System Access, измерение в реальном UI), ИЛИ
- альтернатива явно дороже по ресурсам/времени.

Сначала всегда пробовать дешёвые способы: чтение файлов, `curl`/`Invoke-WebRequest`, лог dev-сервера, поиск по коду/докам. Проверка «работает ли сайт / есть ли ошибка» = HTTP-запрос + лог сервера, НЕ браузер. Если кажется, что нужен браузер — сперва спросить себя, нет ли способа без него, и при сомнении спросить пользователя.

**Запрет не касается редактора статей.** Живая проверка программы во встроенном окне на `localhost:4780` обязательна — порядок в навыке `editor-live-check`. Запрет выше относится к внешнему браузеру с вашей живой сессией (Claude in Chrome, Comet) для рутинных задач и его не отменяет.
